# Подборки ВкусВилла: спецификация

**Дата:** 2026-10-22
**Статус:** согласовано с заказчиком

## 1. Цель

Локальный учебный веб-сервис, который показывает 10–15 подборок продуктов
ВкусВилла («ужин на двоих», «обед с друзьями», «романтический ужин» и т.п.).
Цель — проверить работу официального MCP ВкусВилла, а не сделать продакшен. Подборку можно сохранить в избранное, а кнопка
«В корзину» открывает ссылку на корзину ВкусВилла с товарами подборки.

## 2. Решения

| Вопрос | Решение |
| --- | --- |
| Бэкенд | Go + stdlib `net/http`, один бинарник |
| Фронтенд | HTML/CSS/JS без сборки, встроен в бинарник через `embed` |
| Хранение | SQLite (pure-Go драйвер `modernc.org/sqlite`) |
| Избранное | Анонимный cookie + SQLite |
| Подборки | Фиксированные шаблоны + рандомизация товаров |
| Генерация | Пул при старте; обновление перезапуском сервера |
| Корзина | Публичная ссылка через MCP, без OAuth |
| Запуск | Локально: `make run`, `http://localhost:8080` |

## 3. Пользовательские сценарии

### US-1. Посмотреть подборки
Как гость я открываю сайт и вижу 10–15 разных подборок с названием,
описанием, товарами, ценами и итоговой суммой.

**Критерии приёмки:**
- На странице ровно 12 карточек (значение конфигурируемое, 10–15).
- При обновлении страницы состав и порядок меняются.
- В каждой карточке 3–6 товаров, у каждого — название, количество, цена.
- Для бюджетных подборок итог не превышает бюджет.
- Рейтинг каждого товара не ниже 4.5.

### US-2. Сохранить в избранное
Как гость я нажимаю на карточке «В избранное» и позже нахожу её во вкладке
«Избранное».

**Критерии приёмки:**
- Повторное нажатие убирает подборку из избранного.
- Избранное переживает перезапуск браузера и сервера.
- На вкладке «Избранное» видны те же карточки; кнопка «В корзину» работает.
- Пустое избранное показывает подсказку, а не пустой экран.

### US-3. Открыть корзину
Как гость я нажимаю «В корзину» на подборке и получаю ссылку на корзину
ВкусВилла с этими товарами.

**Критерии приёмки:**
- Кнопка показывает состояние загрузки и блокируется на время запроса.
- Ссылка открывается в новой вкладке.
- Повторное нажатие в течение 24 часов не создаёт новую ссылку (кэш).
- При ошибке MCP показывается понятное сообщение и кнопка снова активна.
- Неизвестная подборка возвращает 404.

### US-4. Актуальность подборок
Как гость я хочу, чтобы подборки обновлялись и не повторялись бесконечно.

**Критерии приёмки:**
- Пул содержит до 18 подборок (18 шаблонов × 1 вариант).
- Пул перегенерируется при старте сервера; старый пул остаётся в БД для
  избранного.
- Ошибка генерации не ломает сайт: отдаётся последний успешный пул.

### US-5. Мобильный сценарий
Как гость я открываю сайт с телефона.

**Критерии приёмки:**
- Одна колонка до 720 px, две до 1100 px, три выше.
- Кнопки и ссылки доступны с клавиатуры, есть видимый фокус.
- При `prefers-reduced-motion` анимации отключаются.

## 4. Функциональные требования

1. `GET /api/collections` отдаёт случайную выборку активного пула и список
   id избранного текущего посетителя.
2. `GET /api/favorites` отдаёт избранные подборки посетителя.
3. `PUT /api/favorites/{id}` и `DELETE /api/favorites/{id}` меняют избранное.
4. `POST /api/collections/{id}/cart` возвращает `{"url": "..."}`; ссылка
   кэшируется в БД на 24 часа.
5. `GET /healthz` — процесс жив; `GET /readyz` — есть активный пул и БД.
6. Cookie `vv_visitor` создаётся при первом запросе: 32 случайных байта,
   HttpOnly, SameSite=Lax, срок 1 год.
7. Все ошибки API — JSON `{"error":"..."}` с корректным HTTP-кодом.

## 5. Нефункциональные требования

- Go 1.27+, один бинарник, без CGO.
- Внешние вызовы MCP: таймаут 30 с, лимит 2 запроса/с, до 3 повторов на 429.
- Кэш поисковых запросов в памяти в пределах одной генерации.
- Структурные логи `slog`, graceful shutdown.
- Первичная генерация занимает около минуты; сервер стартует после неё.
- Секреты только через переменные окружения.

## 6. Вне рамок

- Аккаунты и авторизация пользователей.
- OAuth-корзина конкретного аккаунта ВкусВилла.
- Оформление и оплата заказа.
- LLM-генерация названий и сценариев.
- Публичный деплой, Docker, HTTPS, внешняя БД.
- Отзывы, рейтинги, поиск по подборкам.

## 7. Архитектура

```
Браузер
  │  HTML/CSS/JS (embed)
  ▼
net/http mux ── SQLite (пул, избранное, кэш ссылок)
  │
  └── MCP-клиент (Go SDK) ──► https://mcp.vkusvill.ru/mcp
          ▲
Генератор при старте: 18 шаблонов × 1 вариант
```

Слои: `httpapi` → `store`/`generator` → `mcp` → `domain`. Зависимости
передаются через интерфейсы, внешний MCP подменяется фейком в тестах.

## 8. Данные

### Domain

```go
type Product struct {
    ID       int
    Name     string
    Price    int      // рубли
    Unit     string
    Rating   float64
    Quantity float64
    URL      string
}

type Collection struct {
    ID         string
    Slug       string
    Title      string
    Subtitle   string
    Template   string
    Budget     int      // 0 = без бюджета
    Total      int
    Items      []Product
    Tags       []string
    CartURL    string
    CartSetAt  time.Time
    CreatedAt  time.Time
    Generation int64
    Active     bool
}
```

### SQLite

- `collections(id TEXT PK, slug, title, subtitle, template, budget, total,
  items JSON, tags JSON, cart_url, cart_set_at, generation, active, created_at)`
- `favorites(visitor_id, collection_id, created_at, PK(visitor_id, collection_id))`
- `meta(key, value)` — время последней успешной генерации.
- Старые поколения помечаются `active = 0` и остаются в БД, чтобы избранное
  не ломалось. Автоматическая очистка в MVP не реализована.

## 9. Генерация

Шаблон задаёт сценарий, бюджет (или 0), теги и 3–5 позиций:
`{query, quantity, min_rating, optional}`.

1. Для каждого запроса — поиск MCP (`sort=popularity`, `limit=10`);
   результаты кэшируются на время одной генерации.
2. Берётся первый кандидат с рейтингом не ниже 4.5, уже использованные
   товары пропускаются.
3. Если у шаблона задан бюджет: уменьшаем количества и убираем
   optional-позиции, пока сумма не станет ≤ бюджета; затем добиваем
   optional-позициями до 70% бюджета. Минимум 3 товара.
4. Одна неудачная позиция не роняет всю генерацию: шаблон пропускается,
   ошибка логируется.
5. Если собрано меньше 10 подборок, поколение не сохраняется.

## 10. API

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/collections` | `{collections, favorites}` |
| GET | `/api/favorites` | `{collections}` |
| PUT | `/api/favorites/{id}` | `{favorite:true, id}` |
| DELETE | `/api/favorites/{id}` | `{favorite:false, id}` |
| POST | `/api/collections/{id}/cart` | `{url}` |
| GET | `/healthz` | `ok` (text/plain) |
| GET | `/readyz` | `ready` или 503 |

Отдельного лимита на входящие запросы нет.

## 11. Дизайн

Направление — «рыночный чек и витрина», не SaaS-карточки.

- Палитра: бумага `#FBFBF6`, чернила `#122017`, зелёный `#1B7A3D`,
  лайм `#D8F26B`, томат `#E24A2A`, линия `#D8DCCF`.
- Шрифты: системные (без внешних Google Fonts, чтобы работало офлайн).
- Сетка: адаптивная, `auto-fill` от 280 px.
- Карточка: название, сценарий, список позиций как чек, крупный итог,
  кнопки «В корзину» и «В избранное».
- Без анимаций появления и декоративной нумерации; только спокойный hover.

## 13. Тестирование

- Unit: бюджет, выбор кандидата, парсинг ответов MCP, store, cookie.
- HTTP: httptest + фейковый MCP и фейковое хранилище.
- `go test ./...`, `go vet ./...`.
- Ручной smoke: запуск, ожидание `/readyz`, 12 карточек, избранное,
  создание реальной ссылки на корзину.

## 14. Риски

- MCP может изменить схему ответа — парсинг изолирован и покрыт фикстурами.
- Rate limit 60/мин — генерация последовательная с лимитером и кэшем.
- Ссылки на корзину могут истекать — TTL 24 часа, при ошибке пользователь
  может нажать ещё раз.
- Google Fonts недоступны офлайн — системный fallback, вёрстка не ломается.
