# Конфигурация и эксплуатация

## 1. Переменные окружения

| Переменная | По умолчанию | Валидация | Назначение |
| --- | --- | --- | --- |
| `PORT` | `8080` | Должен быть числом | HTTP-порт |
| `DB_PATH` | `./data/collections.db` | — | Файл SQLite |
| `VV_MCP_URL` | `https://mcp.vkusvill.ru/mcp` | — | Endpoint MCP |
| `VV_ACCESS_TOKEN` | пусто | — | Необязательный bearer-токен для MCP |
| `COLLECTIONS_PER_PAGE` | `12` | Целое от 10 до 15 | Сколько подборок отдавать в одной выборке |
| `CART_LINK_TTL` | `24h` | Положительный `time.Duration` | Срок кэша ссылки на корзину |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` | Уровень `slog` |

Особенности:

- `PORT` проверяется только через `strconv.Atoi`; диапазон 1–65535
  отдельно не проверяется.
- `HTTPTimeout` не настраивается через env и всегда 30 секунд.
- `COLLECTIONS_PER_PAGE` вне диапазона 10–15 приводит к ошибке запуска.
- `CART_LINK_TTL` должен быть положительным; `0` и отрицательные
  значения отклоняются.
- `LOG_LEVEL` разбирается через `slog.Level.UnmarshalText`.

## 2. Запуск

Требуется Go 1.27+.

```sh
cd practices/practice_04/collections
make run
```

Открыть `http://localhost:8080`.

Первая генерация:

- выполняется до старта HTTP-сервера;
- занимает около минуты при доступном MCP;
- требует сеть и доступ к `mcp.vkusvill.ru`;
- при ошибке использует последнее активное поколение из БД;
- если активного поколения нет, процесс завершается с ошибкой.

## 3. Сборка и проверки

```sh
make test    # go test ./...
make vet     # go vet ./...
make build   # CGO_ENABLED=0 go build -o bin/vkusvill-collections ./cmd/server
```

Интеграционный тест с живым MCP:

```sh
go test -tags=integration ./internal/mcp
```

Он читает `VV_MCP_URL` и `VV_ACCESS_TOKEN` из окружения, по умолчанию
идёт на официальный endpoint. Без сети тест не запускайте.

## 4. Логи

- Формат: `slog` TextHandler в `stderr`.
- Уровень: из `LOG_LEVEL`.
- Логируются:
  - старт генерации и её длительность;
  - пропуск шаблона с ошибкой;
  - падение генерации и переход на прошлое поколение;
  - старт прослушивания;
  - каждый HTTP-запрос: метод, путь, статус, длительность;
  - ошибки API с внутренней ошибкой и статусом;
  - паника с путём;
  - ошибка сохранения ссылки на корзину.
- Токен MCP и содержимое cookie в логи не пишутся.

## 5. Health и readiness

| Endpoint | Поведение |
| --- | --- |
| `GET /healthz` | Всегда `200 ok\n`, если процесс жив |
| `GET /readyz` | `200 ready\n`, если есть активная подборка; иначе `503` |

`/readyz` не проверяет доступность MCP: после старта MCP нужен только
для новых генераций и создания ссылок на корзину.

## 6. Отказоустойчивость

| Ситуация | Поведение |
| --- | --- |
| MCP недоступен при старте, активное поколение есть | Сервис стартует на старых данных, пишет warning |
| MCP недоступен при старте, активного поколения нет | Запуск завершается ошибкой |
| MCP недоступен при создании корзины | `502`, кнопка снова активна |
| Ошибка БД при чтении коллекций | `500`, пустой результат не подставляется |
| Ошибка БД при чтении избранного | `500` |
| Ошибка сохранения ссылки на корзину | Ссылка возвращается, ошибка логируется |
| Паника в handler | `recoverer` возвращает `500 internal error` |
| SIGINT/SIGTERM | `Shutdown` с таймаутом 10 секунд |

## 7. Данные и сброс

- БД: `./data/collections.db`.
- WAL-режим создаёт рядом служебные файлы `-wal` и `-shm`.
- Для полного сброса остановите сервис и удалите файл БД.
- Старые поколения не удаляются автоматически; метод `Cleanup` есть,
  но не вызывается.
- Избранное хранится в БД и привязано к cookie, а не к аккаунту.
  Очистка cookie в браузере фактически создаёт нового посетителя.

## 8. Безопасность и ограничения

- Нет авторизации, CSRF-защиты и rate limit на входящие запросы.
- Cookie `HttpOnly`, `SameSite=Lax`, без `Secure` (локальный HTTP).
- MCP-токен передаётся только в заголовке и не логируется.
- Ссылка на корзину публичная и не привязана к аккаунту.
- Сервис учебный; не предназначен для публичного деплоя.
- Нет Docker, HTTPS, внешней БД и фонового обновления.
