# Фронтенд

## 1. Устройство

Фронтенд — три статических файла без сборщика:

- `web/index.html` — разметка, вкладки, сетка, шаблон карточки;
- `web/styles.css` — стили, адаптивная сетка, чипы, фокус;
- `web/app.js` — состояние, загрузка, рендер, избранное, корзина.

Все файлы встроены в бинарник через `//go:embed` в `web/embed.go`.
Внешних библиотек, шрифтов и CDN нет.

## 2. Разметка

| Элемент | Назначение |
| --- | --- |
| `.tabs` | Вкладки «Все» и «Избранное» |
| `#refresh` | Кнопка «Ещё подборки» |
| `#status` | Живой регион `role="status"` для состояний |
| `#tag-bar` | Строка чипов; `role="group"`, доступное имя «Фильтр по тегам» |
| `#grid` | Сетка карточек |
| `#feedback` | Единая панель пустоты и ошибки |
| `#feedback-text`, `#feedback-action` | Текст и действие панели |
| `#notice` | Живой регион для уведомления об исчезнувшем теге |
| `#fav-count` | Счётчик избранного |
| `#card` | `<template>` карточки |

`#grid` не имеет `aria-live`; все состояния объявляются через `#status`
и `#notice`, чтобы не было двойных объявлений.

## 3. Состояние

```js
state = {
  collections: [],
  favorites: new Set(),
  mode: "all",              // "all" | "favorites"
  tags: [],
  activeTag: "",
  loading: false,
  error: null,              // { status, tag, message }
  requestSeq: 0,
  lastRequestTag: "",
  noticeTimer: null,
  focusAll: false
}
```

- `collections` — то, что показано в сетке; на «Все» уже отфильтровано
  сервером.
- `favorites` — множество id избранного; счётчик равен его размеру.
- `tags` — порядок сервера; UI не сортирует и не дедуплицирует.
- `activeTag` — `""` означает «Все».
- `requestSeq` — защита от поздних ответов.
- `lastRequestTag` — что повторять кнопкой «Повторить».
- `focusAll` — нужно ли после рендера поставить фокус на чип «Все».

## 4. Загрузка

### 4.1. `loadCollections(tag)`

Вызывается при первом входе, выборе тега, сбросе, «Ещё подборки» и
повторе.

1. Увеличивает `requestSeq`, запоминает `requestMode = state.mode`.
2. Ставит `loading = true`, сбрасывает `error`.
3. Добавляет `tag` в query только если он непустой; добавляет
   cache-buster `t`.
4. Запрашивает `/api/collections`.
5. Применяет ответ, только если `seq` совпал и `requestMode` всё ещё
   равен `state.mode`.
6. Обновляет `collections` и `favorites`.
7. Обновляет `tags` и `activeTag` только в режиме «Все».
8. Если `activeTag` непустой и отсутствует в `tags`, выполняет
   автосброс: очищает тег, показывает уведомление и загружает все
   подборки.

Ошибки:

- `400` — «Не удалось применить фильтр.» и действие «Сбросить фильтр»;
- `500` с тегом — «Не удалось загрузить подборки по тегу «X».
  Попробуйте ещё раз.» и «Повторить»;
- `500` без тега — «Не удалось загрузить подборки. Попробуйте ещё раз.»
  и «Повторить».

Текст `error.message` и HTTP-коды в сообщениях фильтра не выводятся.

### 4.2. `loadFavorites()`

1. Увеличивает `requestSeq`, ставит `loading = true`.
2. Запрашивает `/api/favorites`.
3. Применяет ответ только в режиме «Избранное».
4. Заменяет `collections` полным списком избранного и синхронизирует
   `favorites` по id из ответа.
5. При ошибке показывает существующее сообщение об избранном.

### 4.3. Переключение вкладок

- На «Избранное»: `mode = "favorites"`, чипы скрываются,
  вызывается `loadFavorites`, `activeTag` сохраняется в памяти.
- На «Все»: `mode = "all"`, вызывается `loadCollections(state.activeTag)`,
  фильтр восстанавливается.

### 4.4. «Ещё подборки»

- На «Все»: `loadCollections(state.activeTag)`, то есть новая случайная
  выборка внутри текущего фильтра.
- На «Избранном»: `loadFavorites()`, то есть заново полный список
  избранного. Это отличается от ранней версии плана, где на «Избранном»
  вызывался `loadCollections` (см. [discrepancies.md](discrepancies.md)).

### 4.5. Повтор

`retry()` вызывает `loadCollections(state.lastRequestTag)`. Кнопка
«Повторить» показывается только для ошибок `500`; для `400`
показывается «Сбросить фильтр».

## 5. Рендер

`render()`:

1. Рисует строку чипов (`renderTagBar`).
2. Очищает сетку.
3. Если `loading` — показывает индикатор, скрывает `#feedback`,
   блокирует `#refresh`.
4. Если есть `error` — показывает панель с текстом и действием.
5. Если карточек нет:
   - на «Все» с фильтром — «По тегу «X» ничего не найдено» и сброс;
   - на «Все» без фильтра — «Подборок пока нет» и «Обновить»;
   - на «Избранном» — существующая подсказка про избранное.
6. Иначе рисует карточки и статус успеха.

### Чипы

- Показываются только в режиме «Все».
- Первый — «Все» с `data-tag=""`, затем `state.tags` в порядке сервера.
- У активного `aria-pressed="true"`, у остальных — `"false"`.
- Во время загрузки всем ставится `aria-disabled="true"`, но нативный
  `disabled` не используется, чтобы не ломать Tab-порядок и фокус.
- Клик и Enter/Space работают одинаково, потому что чип — нативная
  кнопка.
- При фокусе вызывается `scrollIntoView({block:"nearest",
  inline:"nearest"})`.

### Карточка

- Название, подзаголовок, теги.
- Список товаров: название, количество (для кг или `> 1`), цена.
- Итог и бюджет.
- Кнопка избранного `♡/♥` с `aria-pressed`.
- Кнопка «В корзину».

## 6. Избранное и корзина

### Избранное

`toggleFavorite`:

1. Определяет текущее состояние по `state.favorites`.
2. Вызывает `PUT` или `DELETE /api/favorites/{id}`.
3. Обновляет `state.favorites` и счётчик.
4. На «Избранном» при удалении перерисовывает список; иначе меняет
   только кнопку.
5. Показывает статус «Добавили в избранное» или «Убрали из избранного».
6. При ошибке показывает текст с `error.message` — это существующее
   поведение избранного, не относящееся к фильтру.

### Корзина

`openCart`:

1. Сразу открывает пустую вкладку `about:blank`, чтобы браузер не
   заблокировал popup.
2. Блокирует кнопку и показывает «Собираем корзину…».
3. Вызывает `POST /api/collections/{id}/cart`.
4. Переводит открытую вкладку на полученный URL.
5. При ошибке закрывает вкладку и показывает сообщение.
6. В конце разблокирует кнопку.

Ссылка может быть получена из кэша сервера, поэтому повторное нажатие
в течение `CART_LINK_TTL` не создаёт новую ссылку.

## 7. Доступность и мобильная строка

- Все интерактивные элементы — нативные `button`.
- `#tag-bar` — `role="group"` с именем «Фильтр по тегам».
- Активный чип сообщает состояние через `aria-pressed`.
- Во время загрузки чипы остаются в Tab-порядке, но активация
  игнорируется.
- `:focus-visible` задаёт контрастный outline.
- Область нажатия чипа не меньше 44×44 CSS px.
- `#tag-bar`: `display:flex`, `flex-wrap:nowrap`, `overflow-x:auto`,
  `min-width:0`, `overscroll-behavior-x:contain`; страница не получает
  горизонтальную прокрутку.
- После сброса из пустого состояния фокус переходит на «Все».
- Если сфокусированная кнопка действия исчезает после успеха, фокус
  переходит на активный чип или «Все».

## 8. Гонки и поздние ответы

Каждый запрос получает номер `requestSeq` и запоминает режим вкладки.
Ответ применяется только если номер совпал с текущим и режим не
изменился. Это защищает от ситуации, когда поздний ответ «Все»
перезаписывает «Избранное» или наоборот.

`AbortController` не используется; отмена запроса считается
необязательной оптимизацией.

## 9. Ограничения

- Нет автоматических тестов JS; UI проверяется вручную по
  `quickstart.md`.
- Сообщения избранного и корзины по-прежнему используют
  `error.message`; это существующее поведение вне фильтра.
- Фильтр живёт только в памяти вкладки и не сохраняется в URL.
- Нет выбора нескольких тегов, поиска и сортировки.
