# Тестирование

## 1. Команды

```sh
go test ./...
go vet ./...
go test -tags=integration ./internal/mcp
```

`go test ./...` не требует сети: MCP и хранилище подменяются фейками.
Интеграционный тест с живым MCP вынесен под тег `integration`.

## 2. Что покрыто

### `internal/domain`

- `TrimTag`: пробелы, табы, переводы строк, `\u00a0`, пустые строки,
  значимые внутренние пробелы.
- `AvailableTags`: trim, сортировка, дедупликация, выбор варианта с
  большими кодовыми точками, отбрасывание пустых и тегов длиннее 64,
  пустой вход, NUL и управляющие символы.
- `ResolveTag`: регистронезависимое совпадение и отсутствие тега.
- `HasTag`: совпадение по любому тегу, trim тегов данных,
  регистронезависимость, пустой список.

### `internal/httpapi`

- Ответ без тега и с тегом; известный, неизвестный и пустой тег.
- Канонизация регистра и эхо обрезанного неизвестного тега.
- Независимость избранного от фильтра.
- Случайная выборка внутри отфильтрованного пула.
- Один вызов `ActivePool` на запрос; `tags` и `collections` из одного
  среза.
- Ошибки `400`: повторный `tag`, длина 65, битый query, невалидный
  UTF-8; проверяется, что хранилище не вызывалось и в теле нет
  `collections`.
- Граница длины: 64 — `200`, 65 — `400`.
- Внутренние пробелы значимы; внешние пробелы тега данных обрезаются.
- NUL и управляющие символы допустимы.
- Стабильный порядок `tags`.
- `500` при ошибке хранилища, без `collections`.
- `collections`, `tags`, `favorites` всегда массивы, не `null`.
- Cookie `vv_visitor`: выдача и стабильность.
- Избранное: `404` для несуществующей подборки.
- Корзина: кэш, создание и сохранение ссылки, чужой домен, отсутствующая
  подборка, `502` при ошибке MCP.
- `/readyz`: `200` и `503`.

### `internal/store`

- `ActivePool` возвращает только последнее поколение; старое остаётся
  читаемым через `Get`.
- Пустой пул — пустой срез, не `nil`.
- `Cleanup` сохраняет подборки из избранного и удаляет остальные старые.
- Избранное: добавление, идемпотентный повтор, удаление, `ErrNotFound`
  для чужой подборки.
- Кэш корзины: запись, чтение, `ErrNotFound`.
- `LastGeneration` и `HasActive` до и после сохранения поколения.
- `Get` для отсутствующей подборки.

### `internal/generator`

- Все шаблоны собираются, id уникальны, поколение проставлено, минимум
  3 товара, бюджет не превышен, `total` равен сумме.
- Ошибка одного шаблона не роняет генерацию.
- При полном отказе MCP генерация возвращает ошибку.
- Повторные запросы кэшируются в пределах одной генерации.
- Выбор кандидата учитывает рейтинг и уже использованные товары.
- `fitBudget` удаляет optional-позиции и падает, если минимальный набор
  дороже бюджета.

### `internal/mcp`

- Разбор поиска: цены, рейтинг, `&nbsp;`, HTML-сущности.
- `ok:false`, пустой список, битый JSON — ошибки.
- Разбор ссылки на корзину и отказ чужому домену или пустой ссылке.

### `internal/config`

- Значения по умолчанию.
- Ошибки для нечислового `PORT`, `COLLECTIONS_PER_PAGE` вне 10–15,
  невалидного `CART_LINK_TTL`.

## 3. Тестовые двойники

- `internal/testutil.NewFakeMCP` — фейковый MCP: детерминированные
  товары, счётчик поисков, возможность задать ошибку для конкретного
  запроса или для всех.
- `fakeStore` в `server_test.go` — in-memory хранилище с избранным,
  счётчиком `ActivePool` и подменяемой функцией пула.
- Временная SQLite-БД в `t.TempDir()` для тестов хранилища.

## 4. Чего нет

- Автотестов JavaScript: чипы, фокус, гонки и мобильная прокрутка
  проверяются только вручную.
- Зафиксированных evidence ручного E2E-прогона из `quickstart.md`.
- Отдельных тестов на повторные попытки MCP и `resetSession`.
- Нагрузочных и race-тестов (`go test -race` в CI не настроен).
- Тестов на `Cleanup` как часть жизненного цикла: метод покрыт, но в
  приложении не вызывается.

## 5. Интерпретация

Зелёные `go test ./...` и `go vet ./...` подтверждают логику API,
хранилища, генератора и разбора MCP. Они не подтверждают поведение
браузера и реальный сетевой обмен с MCP. Для полной проверки фичи нужен
ручной прогон по `../../practice_05/spec_review/quickstart.md`.
