# Генерация подборок и MCP

## 1. Роль MCP

Сервис использует официальный MCP ВкусВилла по умолчанию:
`https://mcp.vkusvill.ru/mcp` (`VV_MCP_URL`). Клиент лениво открывает
сессию при первом вызове инструмента и переиспользует её.

Используются два инструмента:

| Инструмент | Аргументы | Назначение |
| --- | --- | --- |
| `vkusvill_products_search` | `q`, `limit`, `sort`, `mode` | Поиск товаров для шаблона |
| `vkusvill_cart_link_create` | `products: [{id, q}]` | Публичная ссылка на корзину |

`VV_ACCESS_TOKEN` не обязателен. Если он задан, клиент добавляет заголовок
`Authorization: Bearer <token>` через собственный `http.RoundTripper`.

## 2. Транспорт и устойчивость

- Транспорт: `mcp.StreamableClientTransport`, standalone SSE отключён.
- Таймаут HTTP-клиента и одного вызова — 30 секунд (`HTTPTimeout`).
- Лимитер: `golang.org/x/time/rate`, 2 запроса в секунду, burst 4.
- До 3 попыток на один вызов инструмента.
- Повтор выполняется только для ошибок, в тексте которых есть маркеры
  `429`, `rate limit`, `too many requests`, `timeout`,
  `deadline exceeded`, `connection reset`, `eof`, `fetch failed`.
- Перед повтором сессия сбрасывается (`resetSession`), пауза — 1 секунда,
  затем 2 секунды.
- `MaxRetries: 3` также задан на уровне транспорта.
- Пустой `q` запрещён; `limit` вне диапазона 1–10 приводится к 10;
  пустой `sort` заменяется на `popularity`.
- Для корзины проверяется: `id > 0`, `0.01 <= quantity <= 40`, список
  товаров непустой.
- Ответ MCP считается ошибкой, если `ok == false`, текст пустой или
  ссылка на корзину не начинается с `https://vkusvill.ru/`.

## 3. Парсинг ответов

`internal/mcp/parse.go` разбирает JSON-текст, который вернул инструмент.

Поиск ожидает структуру:

```json
{
  "ok": true,
  "data": {
    "items": [
      {
        "id": 123,
        "name": "Товар",
        "price": {"current": 199.5},
        "unit": "шт",
        "rating": {"average": 4.76},
        "url": "https://vkusvill.ru/..."
      }
    ]
  }
}
```

Преобразование:

- `price.current` округляется до целых рублей;
- `rating.average` округляется до одного знака;
- `quantity` по умолчанию `1`;
- HTML-сущности и `&nbsp;` в названии раскрываются, пробелы по краям
  обрезаются;
- товары с `id <= 0` пропускаются;
- если после фильтрации список пуст, возвращается ошибка
  `search returned no products`.

Корзина ожидает `{"ok": true, "data": {"link": "..."}}`; ссылка
обрезается и проверяется на домен.

## 4. Шаблоны подборок

`internal/generator/templates.go` содержит 18 шаблонов. Каждый задаёт:

- `Slug`, `Title`, `Subtitle`;
- `Budget` (0 — без лимита);
- `Tags []string`;
- `Items []TemplateItem` с полями `Query`, `Quantity`, `MinRating`,
  `Optional`.

Примеры: «Ужин на двоих», «Обед с друзьями», «Романтический ужин»,
«Завтрак за 7 минут», «Пикник в парке», «Здоровый перекус»,
«Паста-вечер», «Русский завтрак», «Детский обед», «В дорогу»,
«Кофе-брейк», «Вегетарианский ужин», «Белковый ужин», «Воскресный
бранч», «Холодный ужин», «Супный день», «Сырная тарелка», «Сладкий
вечер».

Теги заданы в шаблонах и хранятся в `Collection.Tags`. Именно они
попадают в `collections.tags` и участвуют в фильтре.

## 5. Алгоритм генерации

`generator.Generate`:

1. Фиксирует `now` и `generation = now.Unix()`.
2. Создаёт кэш `map[query][]Product` на одну генерацию.
3. Идёт по шаблонам последовательно.
4. Для каждого шаблона вызывает `build`; ошибка шаблона логируется, а
   шаблон пропускается.
5. Если собрано меньше 10 подборок, возвращает ошибку — поколение не
   сохраняется.

`build`:

1. Для каждой позиции шаблона проверяет отмену контекста.
2. Ищет товары через MCP с `limit=10`, `sort=popularity`; результат
   кэшируется по запросу.
3. Берёт первый товар с рейтингом не ниже `MinRating` (по умолчанию 4.5),
   пропуская уже использованные в этой подборке `id`.
4. Если товар не найден:
   - optional-позиция пропускается;
   - обязательная — шаблон считается неудачным.
5. Ставит количество из шаблона или `1`.
6. Если товаров меньше трёх, шаблон отбрасывается.
7. Если задан бюджет, применяет `fitBudget`.
8. Собирает `Collection` с `id = slug-generation`, `total`, `tags`,
   `created_at`, `generation`, `active = true`.

### Бюджет

`fitBudget`:

1. Считает сумму как `round(quantity) * price`.
2. Пока сумма больше бюджета:
   - уменьшает количество самого дорогого товара, у которого
     `quantity > 1`;
   - если такого нет, удаляет последнюю optional-позицию;
   - если не осталось ни того, ни другого — бюджет не помещается,
     шаблон отбрасывается.
3. Если после сокращения осталось меньше трёх товаров, шаблон
   отбрасывается.
4. Пока сумма меньше 70% бюджета:
   - добавляет отсутствующую optional-позицию, если она помещается в
     остаток;
   - иначе увеличивает количество самого дешёвого товара с
     `quantity < 3`.
5. Возвращает итоговый список товаров.

## 6. Сохранение и отказоустойчивость

- Генерация выполняется до старта HTTP-сервера, таймаут — 5 минут.
- `SaveGeneration` сохраняет поколение одной транзакцией.
- Если генерация вернула ошибку, сервис проверяет `HasActive`:
  - есть активное поколение — логирует предупреждение и продолжает
    работу на старых данных;
  - нет активного поколения — завершает запуск с ошибкой.
- Ошибка сохранения поколения не маскируется: запуск завершается
  ошибкой.
- Если MCP вернул меньше товаров или часть шаблонов не собралась, но
  набралось хотя бы 10 подборок, поколение сохраняется.

## 7. Ограничения

- Генерация только при старте; фонового обновления нет.
- Поиск идёт последовательно с лимитером, поэтому первый запуск долгий.
- Один и тот же товар может попасть в разные подборки; внутри одной
  подборки дубли исключаются.
- Цены и наличие зависят от ответа MCP и могут меняться между
  поколениями.
- `limit` поиска ограничен 10, `mode=short`; более подробные данные MCP
  не запрашиваются.
- Ссылка на корзину публичная и не привязана к аккаунту.
