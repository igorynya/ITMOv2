# Архитектура сервиса

## 1. Назначение

`practices/practice_04/collections` — учебный монолитный веб-сервис,
который проверяет работу официального MCP ВкусВилла. Он собирает готовые
подборки продуктов, показывает их в браузере, позволяет сохранить
подборку в избранное и получить публичную ссылку на корзину ВкусВилла.

Сервис не является продакшен-решением: в нём нет авторизации, деплоя,
фонового обновления подборок и очистки старых поколений.

## 2. Компоненты

```text
Браузер
  │  HTML / CSS / JS из embed
  ▼
net/http mux
  ├── internal/httpapi ── internal/store ── SQLite
  │        │
  │        └── internal/mcp ──► https://mcp.vkusvill.ru/mcp
  │
  └── web (index.html, styles.css, app.js)

cmd/server
  ├── internal/config
  ├── internal/store
  ├── internal/generator ── internal/mcp
  └── internal/httpapi
```

| Пакет | Ответственность |
| --- | --- |
| `cmd/server` | Сборка зависимостей, генерация при старте, HTTP-сервер, graceful shutdown |
| `internal/config` | Чтение и валидация переменных окружения |
| `internal/domain` | `Product`, `CartItem`, `Collection`, чистые правила тегов |
| `internal/store` | SQLite: поколения, активный пул, избранное, кэш ссылок, метаданные |
| `internal/mcp` | Клиент официального MCP, лимитер, повторы, парсинг ответов |
| `internal/generator` | 18 шаблонов, поиск товаров, бюджет, сборка подборок |
| `internal/httpapi` | HTTP API, cookie посетителя, статика, логирование, recover |
| `web` | Встроенные через `embed` HTML, CSS и JS |
| `internal/testutil` | Фейковый MCP для тестов |
| `internal/domain/tags.go` | Нормализация, канонизация и фильтрация тегов (фича practice_05) |

Зависимости направлены внутрь: `httpapi` знает про `store` и `domain`,
`generator` — про `mcp` и `domain`, `store` — про `domain`. Внешний MCP
скрыт за интерфейсом `mcp.Client`, поэтому в тестах заменяется фейком.

## 3. Запуск

Последовательность в `cmd/server/main.go`:

1. `config.Load()` читает переменные окружения и проверяет значения.
2. Настраивается `slog` с уровнем из `LOG_LEVEL`.
3. `store.Open(DBPath)` открывает SQLite, создаёт каталог и применяет
   `_pragma=busy_timeout(5000)`, `journal_mode(WAL)`, `foreign_keys(1)`.
4. `store.Migrate()` выполняет идемпотентный `CREATE TABLE IF NOT EXISTS`.
5. Создаётся `mcp.NewRemote(MCPURL, MCPToken, 30s)`.
6. `refresh()` генерирует подборки с таймаутом 5 минут и сохраняет новое
   поколение. Если генерация не удалась, но в БД есть активное поколение,
   сервис продолжает работу со старыми данными. Если активного поколения
   нет, запуск завершается ошибкой.
7. Создаётся HTTP-handler и `http.Server` с `ReadHeaderTimeout` 5 секунд.
8. Сервер слушает `:PORT`.
9. По `SIGINT`/`SIGTERM` выполняется `Shutdown` с таймаутом 10 секунд,
   затем закрываются MCP-клиент и SQLite.

Важно: HTTP-сервер не стартует, пока не завершилась первая генерация.
Поэтому первый запуск с доступным MCP занимает около минуты.

## 4. Потоки запросов

### 4.1. `GET /api/collections`

1. Middleware `visitor` выдаёт или валидирует cookie `vv_visitor`.
2. `logRequests` оборачивает ответ для логирования статуса и времени.
3. `recoverer` перехватывает панику и возвращает `500`.
4. Handler разбирает необязательный `tag` (правила фичи — в
   [feature-tag-filter.md](feature-tag-filter.md)).
5. `store.ActivePool()` одним запросом читает все строки `active = 1`.
6. Из этого же среза строятся `tags`, выполняется фильтрация и случайная
   выборка не больше `PerPage`.
7. Отдельно читается полный список избранного посетителя.
8. Возвращается JSON `{collections, favorites, tags, active_tag}`.

### 4.2. `GET /api/favorites`

Читает избранное посетителя через `store.ListFavorites`. Фильтр по тегу
на этот endpoint не действует.

### 4.3. `PUT`/`DELETE /api/favorites/{id}`

Добавляет или удаляет связь `visitor_id — collection_id`. При добавлении
несуществующей подборки возвращается `404`; удаление идемпотентно.

### 4.4. `POST /api/collections/{id}/cart`

1. Загружает подборку по `id`.
2. Если сохранённая ссылка ещё не старше `CART_LINK_TTL`, возвращает её
   из кэша.
3. Иначе вызывает MCP `vkusvill_cart_link_create` с товарами подборки.
4. Проверяет, что ссылка начинается с `https://vkusvill.ru/`.
5. Сохраняет ссылку в БД и возвращает её. Ошибка сохранения только
   логируется, пользователь всё равно получает ссылку.

## 5. Ключевые решения

| Решение | Причина |
| --- | --- |
| Один Go-бинарник | Простой локальный запуск, без отдельного фронтенд-сборщика |
| `embed` для статики | HTML/CSS/JS всегда доступны вместе с бинарником |
| SQLite через `modernc.org/sqlite` | Pure-Go драйвер, нет CGO |
| Генерация только при старте | Учебный scope, без планировщика и фоновых задач |
| Активное поколение вместо удаления старых | Избранное продолжает работать после перегенерации |
| Один снимок активного пула на запрос | `tags` и `collections` в ответе относятся к одному поколению |
| Анонимный cookie вместо аккаунтов | Избранное переживает перезапуск без авторизации |
| MCP за интерфейсом `mcp.Client` | Тесты не зависят от сети и внешнего сервиса |
| Fallback на последнее активное поколение | Временная недоступность MCP не ломает уже работающий сервис |

## 6. Границы

Вне рамок сервиса:

- аккаунты, авторизация и OAuth-корзина;
- оформление и оплата заказа;
- фоновое обновление подборок и очистка старых поколений;
- деплой, Docker, HTTPS, внешняя БД;
- поиск, сортировка, несколько тегов, сохранение фильтра в URL.

Подробности по данным — в [03-data-storage.md](03-data-storage.md), по
API — в [02-api.md](02-api.md), по генерации — в
[04-generation-and-mcp.md](04-generation-and-mcp.md).
