# Фича: фильтр подборок по тегу

## 1. Что делает

На вкладке «Все» над сеткой появляется строка тегов. Пользователь
выбирает один тег — сервер возвращает только подборки с этим тегом,
не более `COLLECTIONS_PER_PAGE` штук. Повторное нажатие на активный тег
или «Все» снимает фильтр. На «Избранном» фильтр не применяется, но
выбранный тег запоминается и восстанавливается при возврате.

Фича не меняет схему БД, формат `collections.tags`, генератор, API
избранного и корзины. Новых зависимостей нет.

## 2. Пользовательские сценарии

1. Выбрать тег, увидеть только подходящие подборки и один активный чип.
2. Снять фильтр повторным чипом, кнопкой «Все» или действием в пустом
   состоянии.
3. Видеть различимые состояния: загрузка, успех, пустота, ошибка `400`
   или `500`.
4. Получать предсказуемые ответы на пустой, неизвестный, длинный,
   повторённый тег, другой регистр и пробелы.
5. Перейти в «Избранное» и вернуться, не потеряв фильтр.
6. Пользоваться чипами с клавиатуры и на ширине 320 px.

## 3. API

### `GET /api/collections`

Параметры:

| Параметр | Правило |
| --- | --- |
| без `tag` | Весь активный пул |
| `tag=` или только пробелы | Как без тега |
| `tag=X` | Фильтр по каноническому `X` |
| `tag` два и более раз | `400 tag must be specified once` |
| битый percent-encoding | `400 invalid query` |
| невалидный UTF-8 | `400 tag must be valid UTF-8` |
| больше 64 Unicode-символов после обрезки | `400 tag is too long` |

Успешный ответ:

```json
{
  "collections": [],
  "favorites": [],
  "tags": [],
  "active_tag": ""
}
```

- `tags` — все теги активного пула, обрезанные, без пустых и длиннее
  64, без регистронезависимых дублей, отсортированные по кодовым точкам.
- `active_tag` — каноническое написание выбранного тега; для
  неизвестного — обрезанное значение запроса; без фильтра — `""`.
- Неизвестный тег — `200` и `collections: []`, не `404`.
- `collections` — случайная выборка после фильтрации, не больше
  `PerPage`.
- `tags` и `collections` строятся из одного вызова `ActivePool`.
- `favorites` не зависит от фильтра.
- Ошибки `400`/`500` содержат только `error`, без `collections`.
- Массивы всегда `[]`, не `null`.

## 4. Правила тегов

`internal/domain/tags.go`:

- `MaxTagLength = 64` — считается в Unicode-символах
  (`utf8.RuneCountInString`), а не в байтах.
- `TrimTag` — `strings.TrimSpace`: обрезает Unicode-пробелы по краям.
- `AvailableTags`:
  - обрезает теги данных;
  - пропускает пустые и длиннее 64;
  - сравнивает без учёта регистра через `strings.EqualFold`;
  - при вариантах, отличающихся регистром, оставляет лексикографически
    меньший (наименьшие кодовые точки);
  - сортирует результат.
- `ResolveTag` — ищет запрошенный тег среди доступных без учёта
  регистра.
- `HasTag` — сравнивает тег подборки с выбранным без учёта регистра,
  обрезая пробелы у тегов данных.

Внутренние пробелы значимы: «ужин на двоих» и «ужин» — разные теги.
NUL и управляющие символы не запрещены. Unicode-нормализация
(NFC/NFD) не выполняется.

## 5. Серверная реализация

`internal/httpapi/server.go`:

1. `url.ParseQuery` по `RawQuery`; ошибка — `400 invalid query`.
2. Проверка количества значений `tag`; больше одного — `400`.
3. Проверка `utf8.ValidString`.
4. `TrimTag`, проверка длины.
5. Один вызов `store.ActivePool`.
6. `AvailableTags(pool)` и `ResolveTag`.
7. Фильтрация пула через `HasTag`; неизвестный тег даёт пустой срез.
8. `sampleCollections(filtered, PerPage)` — копия, `math/rand.Shuffle`,
   обрезка.
9. Отдельный вызов `ListFavorites` для cookie-посетителя.
10. Ответ с `collections`, `favorites`, `tags`, `active_tag`.

Валидация выполняется до обращения к хранилищу. `Store` больше не
содержит `SampleActive`: интерфейс требует `ActivePool`, а выборка
живёт в HTTP-слое. `ActivePool` читает все строки `WHERE active = 1`
без `ORDER BY`.

## 6. UI

`web/app.js`:

- `loadCollections(tag)` собирает `URLSearchParams`, добавляет
  cache-buster, проверяет `requestSeq` и режим вкладки.
- `renderTagBar` рисует «Все» и `state.tags` в порядке сервера.
  Активный чип — `aria-pressed="true"`.
- При загрузке чипы получают `aria-disabled="true"`, активация
  игнорируется, но Tab-порядок сохраняется.
- `render` различает загрузку, успех, пустоту по тегу, пустоту без
  фильтра, пустоту избранного и ошибку.
- `retry` повторяет `lastRequestTag`; показывается только для `500`.
- При `400` показывается «Сбросить фильтр».
- Если `activeTag` исчез из `tags`, выполняется автосброс с
  уведомлением «Тег больше недоступен, фильтр сброшен» на 5 секунд.
- `refresh` на «Избранном» вызывает `loadFavorites`, на «Все» —
  `loadCollections(state.activeTag)`.
- Переключение вкладок сохраняет `activeTag` в памяти; чипы на
  «Избранном» скрыты.
- Поздние ответы отбрасываются по `requestSeq` и `requestMode`.

`web/index.html` содержит `#tag-bar` (`role="group"`, имя «Фильтр по
тегам»), `#status`, `#feedback`, `#notice`, `#grid`, `#refresh`.

`web/styles.css`:

- чипы в одну строку, `overflow-x: auto`, `min-width: 0`;
- область нажатия не меньше 44×44 px;
- `:focus-visible` с контрастным outline;
- активный чип отличается заливкой, рамкой и начертанием;
- после сброса фокус переходит на «Все».

## 7. Основные сложности реализации

- **Полный список тегов при фильтрации.** Нельзя строить `tags` по
  уже отфильтрованному списку, иначе после выбора тега исчезнут
  остальные чипы. Поэтому `tags` строятся из полного `ActivePool`, а
  фильтр применяется только к `collections`.
- **Один снимок данных.** `tags` и `collections` должны относиться к
  одному поколению. Это достигается одним вызовом `ActivePool`; тест
  подменяет пул и проверяет, что второго вызова нет.
- **Независимость избранного.** Фильтр не должен влиять на
  `favorites` и на вкладку «Избранное». Сервер читает избранное
  отдельно, а UI не применяет тег к `/api/favorites`.
- **Случайная выборка после фильтра.** Если перемешивать весь пул, а
  потом фильтровать, можно получить меньше `PerPage` или ноль.
  Перемешивание выполняется после фильтрации.
- **Гонки вкладок.** Быстрое переключение «Все»/«Избранное» и повторные
  клики дают поздние ответы. Защита — номер запроса плюс режим вкладки.
- **Клавиатура и загрузка.** Нативный `disabled` убрал бы чипы из
  Tab-порядка, поэтому используется `aria-disabled` с программной
  блокировкой.
- **Мобильная строка.** `flex-wrap: nowrap` без `min-width: 0` и
  `overflow-x` растягивает страницу. Прокрутка ограничена `#tag-bar`.
- **Неизвестный и исчезнувший тег.** Неизвестный тег — это не ошибка, а
  пустой результат. Если тег был валиден, но пропал из нового
  поколения, UI сбрасывает фильтр и сообщает об этом.

## 8. Ограничения

- Один тег, без мультивыбора, поиска и сортировки.
- Фильтр не сохраняется в URL и на сервере.
- «Ещё подборки» может повторять ранее показанные карточки.
- Нет автотестов JS и зафиксированного ручного E2E.
- Схема БД не менялась; теги хранятся как есть.
