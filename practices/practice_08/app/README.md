# Подборки ВкусВилла — интерфейс (практика 8)

React 19 + TypeScript + Vite + Tailwind CSS v4 + **shadcn/ui** (компоненты в `src/components/ui`).
Работает поверх реального Go-сервиса `practices/practice_04/collections`; код сервиса и его API не менялись.

Поведение описано в [`../spec.md`](../spec.md), внешний вид — в [`../mockup/`](../mockup/).

## Запуск

```bash
npm install
# 1) сервис (Go 1.27+), порт 8080
cd ../../practice_04/collections && make run
# 2) интерфейс, порт 5173 (запросы /api проксируются на сервис)
cd - && npm run dev
```

Другой адрес сервиса: `API_TARGET=http://host:port npm run dev`.

## Проверки

| Команда | Что делает |
| --- | --- |
| `npm run typecheck` | проверка типов |
| `npm test` | Vitest: юнит- и компонентные тесты, ответы сервера подменяет MSW, проверка доступности axe |
| `npm run e2e:install` | один раз: браузер для Playwright |
| `npm run e2e` | сквозные тесты в Chromium, сеть подменена через `page.route` (Go-сервис не нужен) |

## Где что лежит

- `src/components/ui` — компоненты shadcn/ui (Button, Input, Label, Card, Alert, Badge, Tabs, Skeleton).
- `src/index.css` — токены темы (цвета, радиусы, размер элементов управления). Цвета и радиусы в компонентах берутся только отсюда.
- `src/lib/api.ts` — клиент API, формат ответов проверяется zod.
- `src/lib/validation.ts` — проверка тега (пусто, до 64 символов Unicode).
- `src/hooks` — загрузка списка и избранного; ответ на устаревший запрос игнорируется.
- `src/components` — форма поиска, карточка, сетка, пустые состояния и ошибки.
- `src/test` — данные в формате реального API, обработчики MSW, настройка тестов.
- `e2e` — сквозные тесты Playwright.

## Соответствие критериям практики

- Макет и рабочий интерфейс: `../mockup/` (Replit) и это приложение.
- Библиотека и единый стиль: shadcn/ui, токены в `src/index.css`.
- Основной сценарий: тег → карточки → «В корзину» → ссылка на корзину.
- Форма: валидация, защита от двойной отправки (ref-замок + `disabled`), состояния загрузки, пусто, успех, ошибка (S1–S10 в `spec.md`).
- Тесты клиента: компоненты, взаимодействия, валидация, состояния, полный сценарий; сервер подменён (MSW, Playwright).
- Что делал AI и что исправлено: [`docs/ai-usage.md`](docs/ai-usage.md).

## Проверка, что тесты ловят ошибки (мутации)

Мутация — намеренная временная поломка кода: если соответствующий тест не падает, он ничего не проверяет. Подробный разбор с результатами и скриншотами: [`docs/ai-usage.md`](docs/ai-usage.md#проверка-что-тесты-ловят-ошибки-мутации).

Как повторить (для самой важной защиты, от двойной отправки):

1. В `src/components/TagSearchForm.tsx` закомментируйте строку `if (pending || locked.current) return;` и запустите `npm test`. Упадёт тест «правило 4: два submit в один тик (до перерисовки) дают один запрос» (`expected [ …(2) ] to have a length of 1 but got 2`): без защиты на сервер уходят два запроса вместо одного.
2. Верните строку и снова запустите `npm test`: все тесты проходят.

Другие мутации для проверки:

- В `validation.ts` замените `> MAX_TAG_LENGTH` на `> 100`: упадёт тест на 65 символов.
- В `useCollections.ts` уберите первую проверку `if (id !== sequence.current) return null;`: упадёт тест про поздний ответ.

После проверки верните код.
