## Что сделал AI
1. **Спецификация** `../spec.md`: сценарий, состояния S1–S10, 19 правил поведения, контракт API, таблица «правило → тест».
2. **Макет** в Replit по промпту `../mockup/prompt.md`, затем правка по ревью (`../mockup/REPORT.md`, скриншоты в `../mockup/`).
3. **Интерфейс** на shadcn/ui и токенах темы: клиент API (zod), валидация, хуки загрузки, форма поиска, карточка, пустые состояния и ошибки.
4. **Тесты**: юнит (валидация, склонение, API-клиент), компонентные с подменой сервера MSW, проверка доступности axe, сквозные Playwright, скриншотные Playwright.

## Примеры запросов
- Макет (Replit): промпт из `../mockup/prompt.md` (экраны, состояния загрузки/пусто/ошибка, поле «Тег», кнопки). Правка по ревью: добавить кнопку перехода в корзину ВкусВилла и убрать лишний блок (`../mockup/iterations/`).
- Интерфейс: «Реализуй интерфейс по spec.md на shadcn/ui из src/components/ui, цвета и радиусы бери из токенов src/index.css, API не менять».
- Тесты: «Для каждого правила из таблицы приёмки spec.md напиши тест; ответы сервера подмени через MSW в формате реального API; основной сценарий пройди в Playwright».

## Что проверяют тесты
- `npm test`: 38 тестов (17 юнит + 21 компонентный).
- `npm run e2e`: 4 сквозных теста (основной сценарий, клавиатура, ширина 320 px, ошибка 500) и 7 скриншотных (S1, S2, S3, S6, валидация, S10, 320 px). Эталоны скриншотов созданы на macOS (`-darwin`), на другой ОС их нужно пересоздать: `npm run e2e:visual:update`.
- Тестовые ответы сервера повторяют формат реального API (`src/test/fixtures.ts`); интерфейс дополнительно проверен вручную с настоящим Go-сервисом (`../screenshots/`).

## Проверка, что тесты ловят ошибки (мутации)

**Что это.** Практика требует временно сломать проверяемое поведение и убедиться, что соответствующий тест упадёт, а после восстановления кода снова пройдёт. Такая намеренная поломка называется мутацией: так видно, что тест реально проверяет поведение, а не проходит «вхолостую».

**Что сломали.** Защиту формы от повторной отправки. В `src/components/TagSearchForm.tsx` в `handleSubmit` есть строка:

```ts
if (pending || locked.current) return;
```

Она не пускает вторую отправку: `pending` равно `true`, пока идёт запрос, а `locked` (`useRef`) закрывается синхронно при первой отправке. Мутация: строка закомментирована (`// МУТАЦИЯ (временно): ...`), и каждая отправка формы доходит до сервера.

**Почему тест падает.** Новый тест «правило 4: два submit в один тик» вызывает отправку формы дважды подряд внутри одного `act`, то есть до перерисовки React, когда кнопка «Найти» ещё не стала `disabled`. С защитой первый вызов закрывает замок, второй возвращается сразу: на сервер уходит 1 запрос. Без защиты уходят 2 запроса, и проверка `expect(urls).toHaveLength(1)` падает: `expected [ …(2) ] to have a length of 1 but got 2`.

| Шаг | Результат | Кадр |
| --- | --- | --- |
| 1. Первая версия тестов, защита выключена | **38 из 38 прошли**: мутация не поймана. Тест про двойной клик не доходил до защиты: кнопка уже `disabled`, и браузер блокирует второй клик и Enter | `../../screenshots/mutation-1-not-caught.png` |
| 2. Добавлен тест «два submit в один тик», защита выключена | **упал 1 тест**: `expected [ …(2) ] to have a length of 1 but got 2` | `../../screenshots/mutation-2-caught.png` |
| 3. Строка возвращена | все 39 тестов проходят | `../../screenshots/mutation-3-restored.png` |

**Вывод.** Проверка нашла слабое место в первой версии теста: он не отличал рабочую защиту от сломанной. Тест дополнен, теперь поломка ловится. Для сравнения: отключённая кнопка защищает от двойного клика и Enter, а замок `useRef` нужен для двух событий в один тик (например, быстрый двойной клик до перерисовки).
