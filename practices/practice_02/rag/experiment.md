## 1. Сконструированный RAG-промпт

<context>
- TRAINING_PR.diff: добавлен эндпоинт FastAPI `POST /api/reviews` без валидации тела и без обработки исключений LLM; сервис формирует промпт, вставляя diff целиком. Evidence: TRAINING_PR.diff — app/api.py:35–38; app/review_service.py:19–22.
- CASE.md — Правила репозитория (строки 64–71):
  - SEC-1: «перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи».
  - API-1: «diff длиннее 20 000 символов отклоняется с HTTP 413».
  - REL-1: «внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ».
  - OUT-1: «ответ содержит summary, массив risks и массив checks…».
  - SCOPE-1: «сервис только советует; он не пишет код и не выполняет действия…».
  - QA-1: «риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория».

- context.md — Факты (строки 17–27): ожидается JSON с ключом `diff: string`; выход `{ "comment": string }`; маршрут `/health` возвращает `{status: ok}`.
- FastAPI (официальная документация): ошибки валидации тела запроса по модели Pydantic возвращают статус 422 Unprocessable Entity.
</context>

Инструкции (grounding rules):
- Используй исключительно факты из <context>. Не добавляй правил или предположений вне перечисленного.
- Каждый вывод сопровождай ссылкой на источник: [TRAINING_PR.diff: file:lines], [CASE.md: rule-id или строки], [context.md: раздел], [FastAPI docs].
- Запрещены галлюцинации: если нет подтверждения в <context>, не включай пункт.
- Верни артефакт в формате candidate → evidence → check, не более 3–4 пунктов, строго на русском.

Запрос:
«На основе <context> составь заземлённый артефакт рисков для TRAINING_PR.diff. Для каждого риска укажи:
candidate — краткое описание риска;
evidence — точные ссылки на строки diff и/или правило CASE.md;
check — воспроизводимая проверка с ожидаемым AS IS и требуемым TO BE (с опорой на CASE.md/стандарты). Соблюдай SCOPE-1 и QA-1.»

## 2. Новый заземленный артефакт

Сводка: По TRAINING_PR.diff в API отсутствует валидация входа и обработка исключений; сервис отправляет полный diff во внешний LLM без ограничений. CASE.md задаёт лимит 20 000 символов (413), требование контролируемого ответа при таймауте (10s) и запрет на утечку секретов (SEC-1).

Риски (grounded):
1) candidate: Нет валидации тела запроса для POST /api/reviews
   evidence: [TRAINING_PR.diff: app/api.py:35–38] — доступ к `payload["diff"]` без проверки; [context.md: 17–27] — вход должен содержать `diff: string`; [FastAPI docs] — при валидации по модели ошибка = 422.
   check: POST `/api/reviews` с `{}` → (AS IS) 500 из‑за KeyError; (TO BE) 422 Unprocessable Entity с описанием отсутствующего поля (`diff`).

2) candidate: Нет обработки исключений LLM и контролируемого ответа/таймаута
   evidence: [TRAINING_PR.diff: app/review_service.py:19–22] — `self.llm.generate(prompt)` без try/except; [CASE.md: REL-1] — timeout 10s и контролируемый ответ.
   check: Смоделировать исключение/таймаут LLM → (AS IS) 5xx без маппинга; (TO BE) 502/503 с сообщением об ошибке/таймауте, в пределах 10 секунд.

3) candidate: Неконтролируемый размер diff — нарушает API-1 (слишком длинный payload)
   evidence: [TRAINING_PR.diff: app/review_service.py:19–22] — diff вставляется в промпт без ограничений; [CASE.md: API-1] — >20000 символов → 413.
   check: POST `/api/reviews` с diff длиной 25 000 символов → (AS IS) запрос уходит в LLM; (TO BE) 413 Content Too Large и отказ без вызова LLM.

4) candidate: Отсутствует маскирование секретов в diff перед отправкой во внешний LLM (SEC-1)
   evidence: [TRAINING_PR.diff: app/review_service.py:20–22] — diff вставляется в промпт напрямую; [CASE.md: SEC-1] — требуется удалять токены/пароли/ключи.
   check: Передать diff, содержащий строку вида `token=abcd...` → (AS IS) секрет уходит во внешний LLM; (TO BE) в prompt секрет заменён на `[REDACTED]` согласно SEC-1.

## 3. Оценка надежности
- Контекст CASE.md (SEC-1, API-1, REL-1) устраняет неопределённость исходного ответа: явно определены лимит 20 000 символов и код 413, 10‑секундный timeout и контролируемый ответ, требование редактирования секретов.
- Привязка к TRAINING_PR.diff исключает галлюцинации: ссылки на app/api.py:35–38 и app/review_service.py:19–22 подтверждают отсутствие валидации/обработки.
- Ссылка на FastAPI docs задаёт ожидаемый код 422 для ошибок валидации и снимает двусмысленность 400/422.
- Соблюдение QA-1 гарантирует, что в артефакт не попадают риски без evidence в diff или правилах.
