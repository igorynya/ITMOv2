# Промпт для OpenSpec: спека логики

Запускать в worktree логики, где инициализирован OpenSpec. Скопируй блок
целиком в чат: команда и промпт должны уйти одним сообщением.

```text
/opsx-propose tag-filter-logic

Ты — команда логики. Подготовь OpenSpec change для фичи «фильтр подборок
по тегу». Работай только с логикой: UI не проектируй, код не пиши.

Контекст:
- practices/practice_05/feature-tag-filter.md;
- practices/practice_04/collections/internal/httpapi/server.go;
- internal/store и internal/domain;
- AGENTS.md;
- openspec/project.md, если он есть.

Задача:
- создай change tag-filter-logic;
- сгенерируй proposal.md и delta-спеку в specs/;
- опиши только наблюдаемое поведение API и данных;
- не запускай /opsx-apply.

Обязательно отрази в спеке:
- GET /api/collections?tag=<значение>;
- пустой или отсутствующий tag возвращает все подборки;
- сравнение тега без учёта регистра;
- неизвестный тег: 200 и пустой массив collections;
- tag длиннее 64 символов: 400;
- tags — все доступные теги активного пула;
- active_tag — каноническое значение или пустая строка;
- случайная выборка внутри отфильтрованного набора;
- если подходящих подборок меньше 12, вернуть все;
- избранное и корзина не меняются;
- схема БД не меняется.

Формат:
- proposal.md: зачем нужна фича, границы, не-цели;
- specs/<capability>/spec.md: ADDED Requirements и Scenario в формате
  OpenSpec, с WHEN/THEN;
- каждое требование проверяемое, без CSS, функций и структур кода.

Ограничения:
- не проектируй чипы, экраны и состояния UI;
- не добавляй поиск, сортировку и мультивыбор тегов;
- спорные места вынеси в Open Questions, не решай молча;
- не меняй openspec/specs и не пиши код.

После генерации скопируй результат в
practices/practice_05/spec_logic_openspec/:
- proposal.md;
- всю папку specs/.

Покажи пути к файлам и список открытых вопросов.
```
