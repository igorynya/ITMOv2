## Что и как запускалось

### API

Использован настоящий сервер `cmd/server` на копии БД
(`work/collections.db`), без записи в рабочую `data/collections.db`.
MCP был отключён (`VV_MCP_URL=http://127.0.0.1:9/mcp`), поэтому сервер
отдавал последнее сохранённое поколение — это штатный сценарий из
`quickstart.md`.

```sh
PORT=18080 \
DB_PATH=practices/practice_05/evidence/e2e/work/collections.db \
VV_MCP_URL=http://127.0.0.1:9/mcp \
go run ./cmd/server

python3 practices/practice_05/evidence/e2e/run_api_checks.py \
  --base 127.0.0.1:18080 \
  --out practices/practice_05/evidence/e2e/api-checks.json
```

Проверены: запрос без фильтра, известный тег, другой регистр, пробелы по
краям, пустой тег, неизвестный тег, границы 64/65 символов, повторный
параметр, битый percent-encoding, невалидный UTF-8 и независимость
избранного от фильтра. Все 10 проверок прошли.

### UI

UI-стенд использовал настоящие `web/`, `internal/httpapi` и SQLite-БД
(`work/ui.db`), а вместо внешнего MCP — `testutil.FakeMCP`. Это нужно,
чтобы детерминированно проверить корзину без сетевых вызовов. Сам продукт
не менялся: для запуска использовался временный `cmd/e2eserver`, после
прогона он удалён.

Браузер: системный Google Chrome через Playwright 1.64.1 (headless).
Сценарии 4.2, 4.3, 4.8 и 4.9 используют подмену ответов API через
Playwright route — это предусмотрено самим `quickstart.md`.

```sh
npm install --no-save playwright-core
node practices/practice_05/evidence/e2e/run_ui_checks.cjs
```

Переменные: `BASE_URL` (по умолчанию `http://127.0.0.1:18081`),
`OUT_DIR` (по умолчанию директория скрипта).

## Ограничения

- Внешний MCP не вызывался. Ссылка корзины проверена на `FakeMCP`;
  сетевой сценарий с реальным ВкусВиллом остаётся вне этого прогона.
- Случайная выборка не сравнивалась по точному набору id между разными
  регистрами: проверялись `active_tag`, вхождение тега в каждую карточку
  и неизменность списка `tags`.
- Сценарии с исчезнувшим тегом, пустым `tags` и ошибками воспроизведены
  подменой ответа API, как разрешает `quickstart.md`.
