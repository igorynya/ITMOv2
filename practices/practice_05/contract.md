# Контракт фичи «фильтр подборок по тегу»

Файл заполняет агент-ревьюер после чтения
`practices/practice_05/spec_ui/spec.md` и
`practices/practice_05/spec_logic/spec.md`.

Правила заполнения:

- не оставляй пустых ячеек: если требования нет, пиши «не указано»;
- в колонке «Решение» фиксируй итоговое поведение, а не пересказ споров;
- если решение требует ответа человека, помечай его «открыто» и задай
  вопрос;
- противоречия не решай молча;
- после ответов человека обнови таблицу и итоговую спеку.

## Таблица контракта

| Пункт | UI ожидает | Логика обещает | Решение |
| --- | --- | --- | --- |
| Endpoint и параметр | Не выбирает endpoint и имя параметра. Ожидает получить подборки и доступные теги из одного успешного ответа. | `GET /api/collections?tag=<значение>`; один тег за запрос; отсутствующий или пустой `tag` — без фильтра; повторный `tag` — `400`. | Принимаем `GET /api/collections` с необязательным одним параметром `tag`. «Все» — запрос без параметра. Отдельный `/api/tags` не вводим. UI отправляет выбранное каноническое значение как есть. |
| Список тегов | Одна строка чипов: «Все» первым, затем все доступные теги из последнего успешного ответа в порядке сервера. При фильтре список не сужается. При пустом списке остаётся только «Все». На «Избранном» чипы скрыты. | `tags` — все теги активного пула без дублей и пустых значений, детерминированно упорядочены сервером, не зависят от фильтра и случайной выборки, присутствуют в каждом успешном ответе. | Принимаем `tags` в том же ответе. UI не сортирует и не дедуплицирует теги. В `tags` попадают только значения, пригодные для фильтрации: после обрезки непустые и не длиннее 64 символов Unicode. |
| Неизвестный тег | Пользователь выбирает только теги из списка. Если сохранённый тег исчез, при возврате на «Все» или обновлении списка на «Все» показывается автосброс на «Все» с коротким уведомлением. | Неизвестный тег — `200`, `collections: []`, полные `tags` и `favorites`, `active_tag` — эхо обрезанного запроса; это не `404` и не `400`. | Прямой запрос с неизвестным тегом остаётся `200` и пустым. UI проверяет, что непустой `active_tag` присутствует в `tags`; если его нет, выполняет автосброс на «Все», перезагружает все подборки и показывает короткое уведомление. Пустое состояние с именем исчезнувшего тега не показываем. |
| Пустой тег | «Все» означает отсутствие фильтра; отдельный пустой тег интерфейс не отправляет. | Отсутствующий, пустой или состоящий только из Unicode whitespace `tag` — без фильтра; `active_tag` — пустая строка. Unicode whitespace по краям отбрасывается через `strings.TrimSpace`. | Принимаем: «Все» — запрос без `tag` или с пустым `tag`. Сервер не фильтрует и возвращает `active_tag: ""`. Пустой ответ не считается ошибкой. |
| Слишком длинный тег | Своего лимита длины не задаёт. Ожидает, что любой тег из `tags` можно выбрать. При `400` показывает сообщение о невозможности применить фильтр и действие «Сбросить фильтр». | Тег длиннее 64 символов Unicode после обрезки — `400` с полем `error` до чтения данных. Ровно 64 символа допустимы. | Сервер не включает в `tags` значения длиннее 64 символов после обрезки, поэтому UI не может выбрать такой тег. Ограничение остаётся для прямых клиентов API. UI не добавляет собственную проверку длины. При `400` показывается сообщение без технических деталей и действие сброса, без «Повторить». |
| Битый URL/UTF-8 | Не формирует такие запросы штатно. При ошибке показывает сообщение и действие сброса. | Некорректное percent-encoding или невалидный UTF-8 в `tag` — `400` с полем `error` до чтения данных. | Принимаем явный `400` до обращения к данным: `invalid query` для битого percent-encoding и `tag must be valid UTF-8` для невалидного UTF-8. UI не показывает текст `error` как есть. |
| Ошибки `400`/`500` | При `400` предлагает сбросить фильтр; при `500` — повторить запрос. | `400` — ошибка валидации без подборок; `500` — внутренняя ошибка чтения, не маскируется под пустоту. | При `400` показываются русский текст и «Сбросить фильтр»; «Повторить» не показывается. При `500` показываются русский текст и «Повторить»; повторный `500` снова даёт «Повторить». HTTP-коды и `error.message` не выводятся. |
| Избранное | На «Избранном» чипы скрыты и фильтр не применяется. Выбранный тег сохраняется и восстанавливается при возврате на «Все». Счётчик избранного полный. Поздние ответы не меняют текущую вкладку. | `favorites` всегда полный и не зависит от фильтра. `/api/favorites`, добавление и удаление избранного, корзина работают без изменений. Фильтр не меняет счётчик и поведение избранного. | Принимаем сохранение и восстановление выбранного тега при возврате на «Все». На «Избранном» фильтр не применяется, чипы скрыты; возврат загружает подборки заново с сохранённым тегом. Ответы для неактивной вкладки отбрасываются. |
| Меньше текущего размера страницы | Показывает все найденные карточки, если их меньше текущего размера страницы. Больше не показывает. Не добирает из других тегов. Ноль — пустое состояние, не ошибка. | Случайная выборка применяется после фильтра. Не более текущего размера страницы (сейчас 12) подборок; при меньшем числе — все; при нуле — пустой массив. Внутри одной выборки повторов нет. | Принимаем: текущий размер страницы (сейчас 12) задаётся конфигурацией. Сервер применяет случайную выборку внутри отфильтрованного набора. UI показывает ровно пришедшее и не добирает. Ноль подборок — успешный пустой результат. |
| Регистр и канонический тег | Не нормализует регистр самостоятельно. Активный чип определяет по каноническому значению от сервера. Второй чип для другого регистра не создаёт. | Сравнение регистронезависимое для Unicode через simple case folding (`strings.EqualFold`), без локали, транслитерации и стемминга. Каноническое написание берётся из пула и выбирается детерминированно. `active_tag` — каноническое значение, эхо обрезанного запроса для неизвестного тега или пустая строка. | Принимаем: нормализация и выбор канонического написания — только на сервере. UI отправляет значение из `tags` как есть и выделяет чип по `active_tag`. Каноническое написание — вариант с лексикографически наименьшей последовательностью кодовых точек Unicode после обрезки; `tags` сортируется по возрастанию кодовых точек. |
| URL-состояние | Не сохраняет фильтр в URL и не поддерживает шаринг ссылки. URL-состояние вне фичи. | Серверное состояние фильтра не хранится. Параметр `tag` существует только в запросе к API. Сохранение в URL не входит в фичу. | Фильтр не пишется в адресную строку и не шарится ссылкой. Параметр `tag` используется только для запроса к API; состояние живёт в памяти вкладки «Все». |

### Политика для gaps

Если при планировании или реализации не принято иное, применяются
предложения по умолчанию из `gaps.md`. Любое отклонение фиксируется в
`contract.md` и итоговой `spec.md`.

## Зафиксированные ответы

1. Выбранный тег сохраняется при переходе на «Избранное» и восстанавливается
   при возврате на «Все»; подборки загружаются заново с этим фильтром.
2. Если выбранный тег исчез из `tags`, UI автоматически сбрасывает фильтр на
   «Все», перезагружает все подборки и показывает короткое уведомление.
3. Теги длиннее 64 символов Unicode после обрезки не попадают в `tags`; UI
   не может выбрать такой тег. Ограничение `400` сохраняется для прямых
   клиентов API.
4. Ошибка `400` показывает сообщение и действие «Сбросить фильтр»;
   ошибка `500` показывает сообщение и «Повторить».
5. Некорректное percent-encoding и невалидный UTF-8 в `tag` дают `400` до
   чтения данных; управляющие символы и NUL не запрещаются, Unicode не
   нормализуется, сравнение идёт через `strings.EqualFold`.
