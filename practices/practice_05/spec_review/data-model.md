# Data Model: фильтр подборок по тегу

**Дата**: 2026-10-23

Схема БД не меняется. Все новые сущности — производные от активного пула
или состояние клиента.

## 1. Существующее хранение (без изменений)

### `collections`

| Поле | Тип | Использование в фиче |
| --- | --- | --- |
| `id` | TEXT PK | идентификатор карточки |
| `slug`, `title`, `subtitle`, `template` | TEXT | существующие поля ответа |
| `budget`, `total` | INTEGER | существующие поля ответа |
| `items` | TEXT (JSON) | существующие поля ответа |
| `tags` | TEXT (JSON-массив строк) | источник `tags`, `active_tag` и фильтрации |
| `cart_url`, `cart_set_at` | TEXT/INTEGER | не меняются |
| `generation` | INTEGER | активный пул |
| `active` | INTEGER | фильтр `active = 1` |
| `created_at` | INTEGER | существующее поле ответа |

### `favorites`, `meta`

Не меняются. `favorites` по-прежнему возвращается полностью и не зависит
от фильтра.

## 2. Доменные типы

### `domain.Collection`

Остаётся без изменений. `Tags []string` уже содержит теги подборки и
участвует в JSON карточки. Новые поля в структуру не добавляются.

### Производный «набор доступных тегов»

Не хранится в БД. Строится из активного пула:

```text
availableTags = sorted(unique(canonical(trim(tag))))
```

Правила:

- исходное значение обрезается `strings.TrimSpace`;
- пустое значение отбрасывается;
- значение длиннее 64 Unicode-символов отбрасывается;
- варианты, равные по `strings.EqualFold`, считаются одним тегом;
- каноническое написание — вариант с наименьшей последовательностью
  кодовых точек Unicode;
- результат сортируется по возрастанию кодовых точек;
- исходные `Collection.Tags` не изменяются.

### Состояние запроса фильтра (внутри handler)

| Поле | Тип | Смысл |
| --- | --- | --- |
| `rawTag` | string | значение параметра `tag` как пришло |
| `requestedTag` | string | `TrimSpace(rawTag)` |
| `maxTagRunes` | int | 64 |
| `activeTag` | string | канонический тег, эхо обрезанного запроса или `""` |
| `selectedTag` | string | канонический тег для фильтрации; `""` — без фильтра |
| `known` | bool | запрос совпал с `availableTags` |

Инварианты:

- `requestedTag == ""` => `activeTag == ""`, `known == false`,
  фильтрация не применяется;
- `known == true` => `activeTag == selectedTag` и значение входит в
  `availableTags`;
- `known == false` и `requestedTag != ""` => `activeTag == requestedTag`,
  `collections` пустой;
- `utf8.RuneCountInString(requestedTag) <= 64`;
- `rawTag` валиден как UTF-8, а `RawQuery` успешно разобран; иначе
  запрос отклоняется до чтения данных.

## 3. HTTP-ответ `GET /api/collections`

```json
{
  "collections": [],
  "favorites": [],
  "tags": [],
  "active_tag": ""
}
```

| Поле | Тип | Инвариант |
| --- | --- | --- |
| `collections` | array объектов подборки | не `null`; не более `PerPage`; при фильтре только подборки с тегом |
| `favorites` | array string | не `null`; полный список избранного посетителя; не зависит от фильтра |
| `tags` | array string | не `null`; все доступные теги активного пула; отсортированы; без дублей |
| `active_tag` | string | канонический тег, эхо обрезанного запроса или `""` |

Поля внутри объекта подборки не переименовываются и не удаляются.
`cart_url` остаётся `omitempty`, как сейчас.

### Согласованность

`collections`, `tags` и `active_tag` строятся из одного среза
`ActivePool`, поэтому относятся к одному активному пулу. `favorites`
читается отдельно и намеренно не связан с фильтром.

## 4. Состояние UI

```text
state = {
  mode: "all" | "favorites",
  collections: Collection[],
  favorites: Set<string>,
  tags: string[],
  activeTag: string,          // "" = Все
  loading: boolean,
  error: null | { message, status, tag },
  requestSeq: number,
  lastRequestTag: string,     // "" = запрос всех подборок
  noticeTimer: number | null
}
```

| Поле | Источник | Инвариант |
| --- | --- | --- |
| `mode` | вкладки | на `favorites` чипы скрыты, фильтр не применяется |
| `collections` | ответ API | на `all` уже отфильтрованы сервером; на `favorites` — избранное |
| `favorites` | `favorites` из `/api/collections` или id из `collections` в `/api/favorites` | счётчик = `favorites.size`, не зависит от фильтра |
| `tags` | `tags` из ответа | порядок сервера, UI не сортирует и не дедуплицирует |
| `activeTag` | `active_tag` из ответа | определяет активный чип; сохраняется при переходе на избранное |
| `loading` | запрос | блокирует активацию чипов и «Ещё подборки» |
| `error` | ошибка запроса | содержит только пользовательский текст и статус для выбора «Повторить»/«Сбросить фильтр» |
| `requestSeq` | счётчик | ответ применяется только для последнего запроса; `tags`/`activeTag` — только на «Все» |
| `lastRequestTag` | запрос | нужен для «Повторить» |

### Переходы

| Событие | `loading` | Запрос | Успех | Ошибка |
| --- | --- | --- | --- | --- |
| первый вход | true | без тега | карточки, `activeTag=""` | `500` — «Повторить» |
| выбор тега | true | `tag=<canonical>` | карточки тега или пустота | `500` — «Повторить»; `400` — «Сбросить фильтр» |
| повторный выбор активного тега | true | без тега | все карточки | `500` — «Повторить» |
| «Все» | true | без тега | все карточки | `500` — «Повторить» |
| «Ещё подборки» | true | текущий тег | новая выборка | `500` — «Повторить»; `400` — «Сбросить фильтр» |
| «Повторить» | true | `lastRequestTag` | успех/пустота | снова `500` + «Повторить» |
| переход на «Избранное» | true | `/api/favorites` | избранное, чипы скрыты | существующая ошибка избранного |
| возврат на «Все» | true | сохранённый `activeTag` | карточки с фильтром | `500` — «Повторить»; `400` — «Сбросить фильтр» |
| успех на «Все», а `activeTag` отсутствует в `tags` | true | без тега | все карточки + уведомление | `500` — «Повторить» |

## 5. Инварианты фичи

- Схема БД и формат хранения тегов не меняются.
- `collections`, `tags`, `favorites` — массивы, не `null`.
- В `tags` нет пустых значений, значений длиннее 64 символов и дублей.
- `active_tag` не содержит необрезанных Unicode whitespace по краям.
- При активном фильтре все `collections` содержат выбранный тег.
- Количество `collections` не больше `PerPage` и не больше числа
  подходящих подборок.
- Внутри одной выборки нет повторяющихся `id`.
- `favorites`, счётчик, добавление/удаление и корзина не зависят от
  `activeTag`.
- На «Избранном» чипы не отображаются и фильтр не применяется.
