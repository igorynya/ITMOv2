## User Scenarios & Testing *(mandatory)*

### User Story 1 - Выбрать один тег и увидеть только подходящие подборки (Priority: P1)

Пользователь на вкладке «Все» видит над сеткой строку чипов: «Все» и доступные теги. Он активирует один тег и получает только активные подборки, у которых есть этот тег. Если подходящих больше текущего размера страницы (сейчас 12), показывается случайная выборка этого размера; если меньше — все найденные.

**Why this priority**: это основная ценность фичи — быстро оставить на экране нужные подборки.

**Independent Test**: открыть вкладку «Все», активировать тег «ужин», убедиться, что в сетке только подборки с этим тегом, активен ровно один чип, карточек не больше текущего размера страницы (сейчас 12), а сброс возвращает все подборки.

**Acceptance Scenarios**:

1. **Given** вкладка «Все» и загруженный список тегов, **When** пользователь активирует тег, **Then** интерфейс показывает загрузку, запускает ровно один запрос, блокирует чипы и «Ещё подборки», а после успеха показывает только подборки с выбранным тегом и оставляет активным этот чип.
2. **Given** подборка имеет несколько тегов, **When** пользователь фильтрует по любому из них, **Then** подборка попадает в результат; подборки без этого тега, без тегов и неактивные подборки не попадают.
3. **Given** по тегу больше текущего размера страницы (сейчас 12) активных подборок, **When** загрузка завершилась, **Then** показывается случайная выборка этого размера без повторов внутри выборки.
4. **Given** по тегу меньше текущего размера страницы (сейчас 12) подборок, **When** загрузка завершилась, **Then** показываются все найденные карточки без пустых мест и без добора из других тегов.
5. **Given** по тегу, который есть в списке доступных, не найдено ни одной подборки, **When** загрузка завершилась, **Then** показывается пустое состояние с названием тега и действием сброса; это не ошибка.
6. **Given** параметр тега отсутствует, **When** пользователь открывает вкладку «Все», **Then** возвращается случайная выборка всех активных подборок, как до фичи.
7. **Given** активен фильтр, **When** пользователь нажимает «Ещё подборки», **Then** загружается новая случайная выборка внутри выбранного тега, фильтр сохраняется.
8. **Given** идёт загрузка, **When** пользователь повторно активирует чип, **Then** второй запрос не запускается.

### User Story 2 - Сбросить фильтр и вернуться к «Все» (Priority: P1)

Пользователь может снять фильтр одним действием: повторным нажатием на активный тег, нажатием на «Все» или кнопкой сброса в пустом состоянии.

**Why this priority**: без понятного выхода из фильтра пользователь может застрять на пустом результате или ошибке.

**Independent Test**: активировать любой тег, затем снять фильтр каждым доступным способом и убедиться, что показываются все подборки.

**Acceptance Scenarios**:

1. **Given** активен тег, **When** пользователь повторно активирует этот же чип, **Then** фильтр снят, активен «Все», загружены все подборки.
2. **Given** активен тег, **When** пользователь активирует «Все», **Then** фильтр снят, активен «Все», загружены все подборки.
3. **Given** пустой результат по тегу, **When** пользователь активирует «Сбросить фильтр», **Then** фильтр снят, активен «Все», загружены все подборки, фокус переходит на «Все».
4. **Given** ошибка загрузки по тегу, **When** пользователь активирует «Все» или другой тег, **Then** выполняется новый запрос без сброса интерфейса в исходное состояние.
5. **Given** идёт загрузка, **When** пользователь пытается повторно активировать чип, **Then** второй запрос не запускается.

### User Story 3 - Понятные состояния загрузки, успеха, пустоты и ошибки (Priority: P1)

На каждом шаге пользователь понимает, что происходит: идёт загрузка, подборки найдены, ничего не найдено или произошла ошибка, которую можно повторить.

**Why this priority**: фильтрация зависит от сервера, поэтому состояния и восстановление после ошибки — часть основного сценария.

**Independent Test**: с помощью задержки и недоступности сервера пройти все состояния и убедиться, что каждое имеет текст и доступное действие.

**Acceptance Scenarios**:

1. **Given** первая загрузка страницы, **When** данные ещё не пришли, **Then** на вкладке «Все» виден активный чип «Все», в области сетки — индикатор загрузки; пустое состояние и ошибка не мелькают.
2. **Given** выбран тег, **When** идёт запрос, **Then** выбранный чип остаётся активным, чипы и «Ещё подборки» недоступны, а сообщение загрузки называет выбранный тег.
3. **Given** запрос завершился успешно, **When** пришли подборки, **Then** сетка показывает карточки, статус подтверждает применение фильтра или отсутствие фильтра, индикатор загрузки и пустое состояние скрыты.
4. **Given** по тегу, который есть в списке доступных, нет подборок, **When** запрос завершился успешно, **Then** показывается пустое состояние с названием тега и кнопкой сброса; это не ошибка.
5. **Given** нет ни одной подборки без фильтра, **When** загрузка завершилась, **Then** показывается пустое состояние и действие «Обновить».
6. **Given** первая загрузка завершилась ошибкой `500`, **When** ошибка получена, **Then** показываются сообщение об ошибке и кнопка «Повторить»; чип «Все» остаётся активным, теги могут отсутствовать.
7. **Given** запрос по тегу завершился ошибкой `500`, **When** ошибка получена, **Then** показываются сообщение с названием тега и кнопка «Повторить»; выбранный чип остаётся активным, а чипы снова доступны для смены фильтра или сброса.
8. **Given** показана ошибка загрузки `500`, **When** пользователь нажимает «Повторить», **Then** снова показывается загрузка, кнопка повторного запроса недоступна, а после ответа отображается успех, пустота или ошибка.
9. **Given** любое состояние ошибки, **When** сообщение показано, **Then** пользователь не видит HTTP-коды, имена внутренних полей и другие технические детали.
10. **Given** запрос выполняется, **When** пользователь переключает вкладку, **Then** поздний ответ не меняет содержимое текущей вкладки; при возврате на «Все» данные загружаются заново.
11. **Given** ошибка валидации `400`, **When** сообщение показано, **Then** доступно действие «Сбросить фильтр», а «Повторить» не показывается.

### User Story 4 - Предсказуемые граничные значения тега (Priority: P1)

Клиент API получает предсказуемый ответ на отсутствующий, пустой, неизвестный, слишком длинный и повторённый тег, а также на разный регистр и пробелы по краям.

**Why this priority**: это защищает от ложных ошибок, неограниченного ввода и разных результатов для одного и того же тега.

**Independent Test**: выполнить запросы без параметра, с пустым значением, с пробелами, с неизвестным тегом, с 64 и 65 символами, с повторённым параметром и с разным регистром; сравнить коды, состав подборок, `tags` и `active_tag`.

**Acceptance Scenarios**:

1. **Given** `tag` отсутствует, пуст или состоит только из Unicode whitespace, **When** клиент запрашивает подборки, **Then** фильтр не применяется, `active_tag` равен пустой строке.
2. **Given** тег отсутствует в активном пуле, **When** клиент фильтрует по нему, **Then** ответ `200`, `collections` — пустой массив, `tags` и `favorites` полные; `active_tag` равен обрезанному запросу; это не ошибка.
3. **Given** запрошенный тег длиннее 64 символов Unicode после обрезки, **When** клиент фильтрует, **Then** ответ `400` с полем `error`, подборки не возвращаются.
4. **Given** запрошенный тег ровно 64 символа, **When** клиент фильтрует, **Then** запрос обрабатывается как обычный тег.
5. **Given** параметр `tag` передан несколько раз, **When** клиент фильтрует, **Then** ответ `400` с полем `error`, потому что за запрос допускается один тег.
6. **Given** запрос «ужин», «УЖИН» или « ужин », **When** клиент фильтрует, **Then** набор подборок совпадает, а `active_tag` содержит одно каноническое написание из пула.
7. **Given** в пуле есть варианты тега, отличающиеся только регистром, **When** сервер строит `tags`, **Then** в списке ровно одно значение, и фильтрация по любому регистру даёт один и тот же результат.
8. **Given** в данных активного пула есть тег длиннее 64 символов, **When** сервер строит `tags`, **Then** это значение в список не попадает и не может быть выбрано в интерфейсе.
9. **Given** `tag` содержит некорректное percent-encoding или невалидный UTF-8, **When** клиент запрашивает подборки, **Then** ответ `400` с полем `error`, подборки не возвращаются.
10. **Given** `tag` содержит таб, перевод строки или NBSP по краям, **When** клиент фильтрует, **Then** эти символы обрезаются, а пробельные символы внутри значения остаются значимыми.

### User Story 5 - Вкладка «Избранное» и возврат на «Все» (Priority: P2)

Фильтр относится только к вкладке «Все». На «Избранном» пользователь видит все избранные подборки и не отвлекается на чипы; при возврате на «Все» ранее выбранный тег восстанавливается.

**Why this priority**: важно не сломать существующее избранное и не создать иллюзию, что фильтр действует на него.

**Independent Test**: выбрать тег, перейти в «Избранное», проверить полный список избранного и вернуться на «Все»; фильтр должен восстановиться.

**Acceptance Scenarios**:

1. **Given** на «Все» выбран тег, **When** пользователь переходит на «Избранное», **Then** чипы скрыты, показываются все избранные подборки, счётчик избранного не меняется, фильтр к избранному не применяется.
2. **Given** пользователь на «Избранном», **When** он возвращается на «Все», **Then** ранее выбранный тег снова активен и подборки загружаются с этим фильтром.
3. **Given** выбранный тег исчез из доступных, **When** пользователь возвращается на «Все» или обновляет список на «Все», **Then** фильтр сбрасывается на «Все», показываются все подборки и появляется короткое уведомление о сбросе.
4. **Given** запрос фильтра ещё выполняется, **When** пользователь переходит на «Избранное», **Then** поздний ответ не заменяет содержимое «Избранного»; при возврате на «Все» фильтр загружается заново.
5. **Given** пустое или ошибочное состояние «Избранного», **When** вкладка открыта, **Then** чипы фильтра не показываются, а существующее поведение загрузки, пустоты и ошибки избранного сохраняется.
6. **Given** карточка в отфильтрованном списке, **When** пользователь добавляет её в избранное или открывает корзину, **Then** действие работает, фильтр не сбрасывается, счётчик избранного обновляется.
7. **Given** активный фильтр, **When** клиент запрашивает список избранного, **Then** список не фильтруется и не меняется.

### User Story 6 - Клавиатура и мобильная прокрутка чипов (Priority: P2)

Пользователь без мыши и пользователь на узком экране могут добраться до любого тега, выбрать его и сбросить фильтр.

**Why this priority**: чипы — основной орган управления фильтром; если до них не добраться, фича недоступна.

**Independent Test**: пройти все чипы только клавиатурой; отдельно открыть страницу на ширине 320 px и проверить прокрутку строки чипов.

**Acceptance Scenarios**:

1. **Given** клавиатурный фокус на вкладках, **When** пользователь нажимает Tab, **Then** фокус последовательно проходит по «Все» и тегам в визуальном порядке; Shift+Tab возвращает назад.
2. **Given** фокус на чипе, **When** пользователь нажимает Enter или Space, **Then** чип активируется так же, как при нажатии мышью.
3. **Given** фокус на чипе, **When** он видим, **Then** у чипа есть заметная рамка фокуса, а активный чип сообщает нажатое состояние через `aria-pressed`.
4. **Given** идёт загрузка, **When** пользователь перемещает фокус по чипам, **Then** чипы остаются в порядке фокуса, но не запускают запрос и объявляются недоступными.
5. **Given** пустой результат, **When** пользователь нажимает кнопку сброса, **Then** фокус оказывается на чипе «Все».
6. **Given** ширина экрана 320 px, **When** тегов больше, чем помещается, **Then** строка чипов остаётся одной строкой с горизонтальной прокруткой, страница не получает горизонтальную прокрутку, а последний чип достижим.
7. **Given** чип получил клавиатурный фокус, **When** он находится за пределами видимой части строки, **Then** строка прокручивается и показывает этот чип.
8. **Given** пользователь прокручивает строку чипов пальцем, **When** прокрутка заканчивается, **Then** выбранный тег не меняется случайно.

### Edge Cases

- Сервер вернул пустой список тегов: показывается только «Все», фильтрация недоступна, подборки отображаются без фильтра.
- Выбранный тег пропал из списка доступных после успешной загрузки: фильтр автоматически сбрасывается на «Все» с коротким уведомлением.
- Тег есть в списке, но по нему нет подборок: это пустой результат, а не ошибка; доступен сброс.
- Подходящих подборок больше текущего размера страницы (сейчас 12): сервер возвращает случайную выборку этого размера без повторов; интерфейс показывает не больше этого размера.
- Подходящих подборок 0, 1 или 11: возвращается ровно столько, сколько есть.
- Ошибка при первой загрузке: доступны только «Все» и повтор; после успешного повтора появляются теги.
- Переключение вкладок во время запроса: поздний ответ не смешивает отфильтрованные подборки с избранным.
- Быстрые повторные нажатия по чипам: пока идёт запрос, второй запрос не запускается.
- Нажатие «Ещё подборки» при активном фильтре: загружается новая случайная выборка внутри выбранного тега, фильтр сохраняется.
- Изменение избранного или открытие корзины на отфильтрованной карточке: фильтр и состояние избранного не ломаются.
- Очень длинное название тега: чип остаётся читаемым, строка чипов прокручивается, текст не обрезается до нечитаемого состояния.
- Тег в другом регистре: интерфейс не создаёт второй чип; активным считается чип, соответствующий каноническому значению, которое вернул сервер.
- В активном пуле нет ни одной подборки: `collections: []`, `tags: []`, `active_tag` — пустая строка или эхо запроса по правилам контракта.
- У подборки пустой массив тегов: она не совпадает ни с одним непустым тегом.
- В одной подборке тег повторяется или отличается регистром: подборка совпадает, а в списке тегов дубля нет.
- Тег в данных пустой или состоит из Unicode whitespace: в `tags` не попадает и ни с чем не совпадает.
- Запрошенный тег состоит только из Unicode whitespace: считается пустым, фильтр не применяется.
- В запросе несколько параметров `tag`: `400`, даже если значения совпадают.
- Значение тега содержит кириллицу и URL-кодирование: сервер сравнивает раскодированное значение.
- Длина тега измеряется в символах Unicode, а не в байтах: 64 кириллических символа допустимы, 65 — нет.
- Тег длиннее 64 символов есть в данных: он не попадает в `tags`, поэтому интерфейс не может его выбрать.
- Некорректное percent-encoding или невалидный UTF-8 в `tag`: `400` с полем `error`, подборки не возвращаются.
- Таб, перевод строки или NBSP по краям тега обрезаются; внутри значения они значимы.
- NUL и управляющие символы внутри тега не запрещаются; Unicode-нормализация не применяется.
- Поколение данных сменилось между запросами: каждый ответ внутренне согласован — `tags` и отфильтрованные подборки относятся к одному активному пулу.
- Избранная подборка стала неактивной: её поведение в избранном не меняется этой фичей.

## Requirements *(mandatory)*

### Functional Requirements

**API и фильтрация**

- **FR-001**: Система MUST предоставлять `GET /api/collections` с необязательным одним параметром `tag`; отдельный endpoint для списка тегов MUST NOT добавляться.
- **FR-002**: Система MUST фильтровать только по активным подборкам текущего поколения; неактивные подборки MUST NOT попадать в `collections`.
- **FR-003**: Подборка MUST считаться подходящей, если хотя бы один её тег совпадает с запрошенным без учёта регистра после обрезки Unicode whitespace по краям (`strings.TrimSpace`); пробельные символы внутри значения значимы; транслитерация, удаление диакритики и стемминг MUST NOT применяться. Unicode whitespace по краям у значений тегов из данных MUST отбрасываться при сравнении; исходные данные MUST NOT перезаписываться.
- **FR-004**: Фильтр MUST поддерживать ровно один тег за запрос; несколько значений `tag` MUST приводить к `400` до обращения к данным.
- **FR-005**: Отсутствующий, пустой или состоящий только из Unicode whitespace `tag` MUST означать отсутствие фильтра и `active_tag: ""`.
- **FR-006**: Неизвестный тег MUST давать `200` с `collections: []`, полными `tags` и `favorites`; это MUST NOT быть `404` или `400`.
- **FR-007**: Запрошенный тег длиннее 64 символов Unicode после обрезки MUST отклоняться с `400` и полем `error` до обращения к данным; ровно 64 символа MUST приниматься.
- **FR-007a**: Некорректное percent-encoding или невалидный UTF-8 в значении `tag` MUST отклоняться с `400` и полем `error` до обращения к данным.
- **FR-008**: Ошибка валидации MUST NOT содержать подборок; внутренняя ошибка чтения данных MUST оставаться `500` и MUST NOT маскироваться под пустой результат.
- **FR-009**: Успешный ответ MUST сохранять существующие поля подборки и `favorites`, добавлять только `tags` и `active_tag`; `collections`, `tags` и `favorites` MUST быть массивами, а не `null`, даже при пустом результате.
- **FR-010**: Случайная выборка MUST применяться внутри отфильтрованного набора; ответ MUST содержать не более текущего размера страницы (сейчас 12) подборок, при меньшем числе — все, при нуле — пустой массив; внутри одной выборки подборки MUST NOT повторяться.
- **FR-011**: Без фильтра система MUST возвращать случайную выборку всех активных подборок в прежнем объёме и формате.
- **FR-012**: `favorites` в ответе MUST содержать полный список избранного посетителя независимо от фильтра; список избранного, добавление, удаление, счётчик и кэш ссылки на корзину MUST работать без изменений.
- **FR-013**: `tags` и отфильтрованные подборки в одном ответе MUST относиться к одному активному пулу.

**Список тегов и каноническое написание**

- **FR-014**: Ответ MUST содержать `tags` — все теги активного пула, пригодные для фильтрации. Значения из данных перед включением в `tags` и сравнением MUST обрезаться по краям (`strings.TrimSpace`, Unicode whitespace); после обрезки они MUST быть непустыми и не длиннее 64 символов Unicode, без дублей, только те, что есть хотя бы у одной активной подборки. Исходные данные MUST NOT перезаписываться.
- **FR-015**: `tags` MUST NOT сужаться до тегов отфильтрованного результата, MUST NOT зависеть от случайной выборки и MUST присутствовать в каждом успешном ответе, включая запрос без фильтра и пустой результат.
- **FR-016**: Порядок `tags` MUST быть детерминированным для одного набора данных и задаваться сервером: канонические значения сортируются по возрастанию кодовых точек Unicode независимо от случайной выборки и текущего фильтра; UI MUST NOT сортировать или дедуплицировать теги самостоятельно.
- **FR-017**: Каноническое написание тега MUST браться из активного пула и выбираться детерминированно: среди вариантов после обрезки выбирается вариант с лексикографически наименьшей последовательностью кодовых точек Unicode. `tags` и `active_tag` MUST использовать одно и то же написание; варианты, отличающиеся только регистром, MUST представлять один тег.
- **FR-018**: `active_tag` MUST содержать каноническое написание при совпадении с пулом, обрезанный запрос при отсутствии совпадения и пустую строку при отсутствии фильтра; `active_tag` MUST NOT содержать пробелов по краям.
- **FR-019**: UI MUST отображать `tags` в порядке сервера, первым — «Все»; UI MUST NOT нормализовать регистр, сортировать, объединять или придумывать теги самостоятельно.
- **FR-020**: Если сервер вернул пустой `tags`, UI MUST показывать только «Все», а подборки — без фильтра.

**Строка чипов и состояния интерфейса**

- **FR-021**: На вкладке «Все» над сеткой MUST отображаться одна строка чипов: первым «Все», затем все доступные теги.
- **FR-022**: Одновременно MUST быть активен только один чип: «Все» — когда фильтр не применён, тег — когда применён фильтр по этому тегу.
- **FR-023**: Активный чип MUST быть визуально отличим, MUST иметь `aria-pressed="true"` (неактивные — `aria-pressed="false"`), а группа чипов MUST иметь доступное имя; активное состояние MUST отличаться от неактивного не только цветом, контраст MUST соответствовать WCAG AA.
- **FR-024**: Активация тега MUST выбирать этот тег, переводить интерфейс в состояние загрузки и запускать ровно один запрос; чипы и «Ещё подборки» на время запроса MUST быть недоступны.
- **FR-025**: Во время загрузки в области сетки MUST показываться индикатор загрузки вместо карточек; пустое состояние и ошибка в это время MUST NOT показываться; сообщение загрузки MUST называть выбранный тег.
- **FR-026**: После успешной загрузки сетка MUST показывать только подборки с выбранным тегом или все подборки без фильтра, не более текущего размера страницы (сейчас 12) карточек; статус MUST подтверждать, что показано; индикатор загрузки, пустое состояние и ошибка MUST быть скрыты.
- **FR-027**: Если по выбранному тегу, который присутствует в `tags`, подборок нет, MUST показываться пустое состояние с названием тега и кнопкой «Сбросить фильтр»; это состояние MUST NOT считаться ошибкой.
- **FR-028**: Если подборок нет без фильтра, MUST показываться пустое состояние с кнопкой «Обновить», которая повторяет загрузку всех подборок.
- **FR-029**: При ошибке `500` первой загрузки MUST показываться сообщение об ошибке и кнопка «Повторить»; чип «Все» остаётся активным, теги могут отсутствовать.
- **FR-030**: При ошибке `500` загрузки по тегу MUST показываться сообщение с названием тега и кнопка «Повторить»; выбранный чип остаётся активным, а чипы снова доступны для смены фильтра или сброса. При ошибке `400` действует FR-031.
- **FR-031**: При ошибке `500` нажатие «Повторить» MUST повторять последний неуспешный запрос с тем же тегом или без тега, переводить интерфейс в загрузку и блокировать повторное нажатие до ответа; повторная ошибка `500` MUST снова показывать сообщение и доступную кнопку «Повторить». При ошибке `400` интерфейс MUST показывать сообщение о невозможности применить фильтр и действие «Сбросить фильтр»; «Повторить» для `400` MUST NOT показываться.
- **FR-032**: Пока идёт запрос, повторная активация чипов MUST NOT запускать второй запрос.
- **FR-033**: Ответ, запрошенный для вкладки, которая уже не активна, MUST NOT изменять содержимое текущей вкладки; при возврате на «Все» данные MUST загружаться заново с сохранённым фильтром.
- **FR-034**: Если сохранённый тег отсутствует в актуальном `tags`, интерфейс MUST сбросить фильтр на «Все», загрузить все подборки и показать уведомление «Тег больше недоступен, фильтр сброшен». Уведомление MUST быть видимым около 5 секунд, MUST NOT быть модальным окном и MUST объявляться через живой регион.
- **FR-035**: Сообщения об ошибке MUST быть понятны пользователю, MUST быть на русском языке и MUST NOT содержать HTTP-коды, имена внутренних полей и другие технические детали; весь текст интерфейса фильтра MUST быть на русском языке.
- **FR-036**: Загрузка, успех, пустой результат и ошибка MUST объявляться программе экранного доступа через живой регион и MUST быть различимы по тексту, а не только по цвету.
- **FR-037**: После успешной загрузки MUST NOT оставаться видимыми индикатор загрузки, сообщение об ошибке или пустое состояние, не относящееся к текущему результату.

**Сброс и обновление выборки**

- **FR-038**: Повторная активация активного тега MUST снимать фильтр, делать активным «Все» и загружать все подборки.
- **FR-039**: Активация «Все» MUST снимать любой фильтр и загружать все подборки.
- **FR-040**: Кнопка «Сбросить фильтр» в пустом состоянии MUST снимать фильтр, активировать «Все», загружать все подборки и переводить фокус на чип «Все».
- **FR-041**: «Ещё подборки» при активном фильтре MUST загружать новую случайную выборку внутри выбранного тега и сохранять фильтр; без фильтра — загружать новую случайную выборку всех активных подборок в пределах текущего размера страницы; во время любой загрузки «Ещё подборки» MUST быть недоступна.
- **FR-042**: Добавление в избранное и открытие корзины на отфильтрованных карточках MUST работать как раньше, MUST NOT сбрасывать фильтр и MUST обновлять счётчик избранного.

**Вкладка «Избранное»**

- **FR-043**: На вкладке «Избранное» чипы фильтра MUST быть скрыты, а фильтр MUST NOT применяться: показываются все избранные подборки.
- **FR-044**: Счётчик избранного MUST показывать общее количество избранных подборок независимо от фильтра.
- **FR-045**: Выбранный на «Все» тег MUST сохраняться при переходе на «Избранное» и восстанавливаться при возврате на «Все»; подборки при возврате MUST загружаться с этим фильтром.
- **FR-046**: Существующие состояния «Избранного» — загрузка, пустота, ошибка — MUST сохраняться; чипы фильтра к ним MUST NOT добавляться.
- **FR-047**: Список избранного MUST NOT фильтроваться; избранное и корзина MUST NOT зависеть от фильтра.

**Клавиатура, мобильная строка и доступность**

- **FR-048**: Все чипы MUST быть достижимы клавишей Tab в визуальном порядке; Shift+Tab MUST возвращать фокус назад.
- **FR-049**: Enter и Space на чипе MUST активировать его так же, как нажатие мышью.
- **FR-050**: Фокус MUST быть всегда видимым.
- **FR-051**: Во время загрузки чипы MUST оставаться в порядке фокуса, но MUST игнорировать активацию и объявляться недоступными; фокус MUST NOT теряться из-за блокировки.
- **FR-052**: Если активированный элемент исчезает (кнопка сброса в пустом состоянии или кнопка повтора после успеха), фокус MUST переходить на «Все» или на активный чип.
- **FR-053**: На узком экране чипы MUST располагаться одной строкой с горизонтальной прокруткой и MUST NOT переноситься на несколько строк; горизонтальная прокрутка строки MUST NOT вызывать горизонтальную прокрутку всей страницы.
- **FR-054**: Последний чип MUST быть достижим прокруткой, а «Все» MUST оставаться первым элементом строки; при получении клавиатурного фокуса чип MUST прокручиваться в видимую область строки.
- **FR-055**: Область нажатия каждого чипа MUST быть не меньше 44×44 CSS-пикселей; прокрутка строки чипов MUST NOT менять выбранный тег.

**Совместимость и границы**

- **FR-056**: Схема БД, формат хранения тегов и существующий формат ответа MUST NOT меняться; меняются только правила выборки и добавляются `tags` и `active_tag`.
- **FR-057**: Формат ошибок и коды остальных эндпоинтов MUST NOT меняться; ошибки валидации фильтра MUST использовать поле `error`.
- **FR-058**: Фича MUST NOT добавлять выбор нескольких тегов, поиск по тексту, сортировку, счётчики подборок на чипах, сохранение фильтра в URL или на сервере.
- **FR-059**: Фича MUST NOT менять поведение корзины и избранного, кроме скрытия чипов на вкладке «Избранное».

### API Contract (agreed)

Запрос:

```http
GET /api/collections?tag=ужин
Accept: application/json
```

Без фильтра параметр `tag` не передаётся или передаётся пустым.

Успех `200`:

```json
{
  "collections": [
    {
      "id": "dinner-500-1792666479",
      "title": "Ужин на двоих",
      "tags": ["ужин", "бюджет"],
      "items": [],
      "total": 0
    }
  ],
  "favorites": ["friends-lunch-1792666479"],
  "tags": ["завтрак", "перекус", "ужин"],
  "active_tag": "ужин"
}
```

- Поля подборки — существующие, без переименований.
- `tags` — полный список доступных для фильтрации тегов активного пула в порядке сервера.
- `active_tag` — каноническое значение, обрезанный запрос для неизвестного тега или пустая строка.
- `collections`, `tags`, `favorites` — массивы, в том числе при пустом результате.

Ошибка валидации `400`:

```json
{ "error": "tag is too long" }
```

Другие ошибки валидации используют то же поле `error`, например
`{ "error": "tag must be specified once" }`, `{ "error": "invalid query" }`
для некорректного percent-encoding и `{ "error": "tag must be valid UTF-8" }`
для невалидного UTF-8. Текст поля `error` предназначен для машинной
обработки и не выводится пользователю как есть.

Внутренняя ошибка `500`:

```json
{ "error": "cannot load collections" }
```

### Key Entities

- **Подборка**: активная запись текущего поколения с идентификатором, набором тегов, содержимым и признаком активности. В фильтрации участвует только активная подборка; её теги — единственный источник совпадений.
- **Тег**: значение из набора тегов подборки. Один тег может входить в несколько подборок; группа написаний, различающихся только регистром, представляет один тег с одним каноническим написанием.
- **Набор доступных тегов**: производное от активного пула множество канонических тегов без дублей и пустых значений, пригодных для фильтрации. Не хранится отдельно и не зависит от текущего фильтра.
- **Избранное посетителя**: связь посетителя с подборками, не зависящая от фильтра, активности подборки и текущей выборки.
- **Кэш ссылки на корзину**: сохранённая ссылка подборки со сроком жизни, не зависящая от фильтра.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь применяет фильтр одним действием и видит только подборки выбранного тега; все сценарии AC из user stories проходят без исключений.
- **SC-002**: Сброс фильтра доступен одним действием из любого состояния, где он применён, включая пустой результат и ошибку.
- **SC-003**: В сетке никогда не больше текущего размера страницы (сейчас 12) карточек; при меньшем числе подходящих отображается точное количество без пустых мест и без добора из других тегов.
- **SC-004**: Каждое из состояний — загрузка, успех, пустота, ошибка — имеет текст и отличимо без опоры только на цвет.
- **SC-005**: Пользователь без мыши может добраться до каждого чипа, сброса, повтора и вкладок, активировать их и всегда видеть фокус.
- **SC-006**: На ширине 320 px строка чипов прокручивается до последнего элемента, а ширина страницы не превышает ширину экрана.
- **SC-007**: При восстановлении сервера кнопка «Повторить» возвращает интерфейс в состояние успеха или пустоты без перезагрузки страницы.
- **SC-008**: Переключение вкладок не смешивает отфильтрованные подборки с избранным и не меняет счётчик избранного.
- **SC-009**: Добавление в избранное и открытие корзины работают до и после фильтрации без регрессий.
- **SC-010**: Программа экранного доступа объявляет загрузку, результат, пустоту и ошибку, а активный чип сообщает нажатое состояние.
- **SC-011**: 100% запросов с отсутствующим или пустым тегом дают прежнее поведение и полный список доступных тегов.
- **SC-012**: Все варианты регистра одного тега, присутствующего в пуле, дают один и тот же набор подборок и одно и то же значение `active_tag`.
- **SC-013**: Ни один успешный ответ не содержит больше текущего размера страницы (сейчас 12) подборок и ни один отфильтрованный ответ не содержит подборок без выбранного тега.
- **SC-014**: Неизвестный тег длиной не более 64 символов всегда даёт `200`, а тег длиннее 64 символов — `400`; других кодов для этих случаев нет.
- **SC-015**: `favorites` и операции избранного не отличаются при включённом и выключенном фильтре.
- **SC-016**: Список тегов детерминирован для одного набора данных и не зависит от случайной выборки.
- **SC-017**: Для одного ответа список тегов и подборки относятся к одному активному пулу; схема БД не меняется.
- **SC-018**: Выбранный тег сохраняется при переходе на «Избранное» и восстанавливается при возврате; при исчезновении тега фильтр сбрасывается с уведомлением.

## Assumptions

- Один тег на запрос; несколько параметров `tag` считаются ошибкой `400`.
- 12 — текущий размер страницы. Сервер использует настроенный размер страницы; UI отображает столько карточек, сколько пришло, и не добирает и не обрезает по жёсткому числу 12.
- Активный пул — текущее поколение данных. Смена поколения между запросами допустима, но каждый ответ внутренне согласован.
- Теги в данных могут содержать Unicode whitespace по краям; сервер обрезает их через `strings.TrimSpace` при построении `tags` и сравнении; пробельные символы внутри значения значимы. Значения, ставшие пустыми, и значения длиннее 64 символов Unicode после обрезки в `tags` не попадают. Исходные данные не перезаписываются.
- Каноническое написание выбирается детерминированно и не меняется между запросами: среди вариантов после обрезки выбирается вариант с лексикографически наименьшей последовательностью кодовых точек Unicode. `tags` сортируется по возрастанию кодовых точек Unicode.
- Сервер не вводит дополнительных запретов на управляющие символы и NUL и не нормализует Unicode (NFC/NFD); сравнение идёт по обрезанным значениям как есть. Некорректное percent-encoding и невалидный UTF-8 отклоняются с `400` до обращения к данным.
- Если при планировании или реализации не принято иное, применяются предложения по умолчанию из `gaps.md`; любое отклонение фиксируется в `contract.md` и этой спеке.
- Регистронезависимость — Unicode simple case folding (`strings.EqualFold`) без локали, транслитерации, синонимов, стемминга и эвристик. UI отправляет выбранное значение как есть, а активным считает чип по `active_tag`.
- Для неизвестного тега `active_tag` равен обрезанному запросу как эху, потому что канонического написания в пуле нет. UI использует это значение, чтобы отличить устаревший тег от известного тега с пустым результатом.
- Выбранный тег сохраняется в памяти при переходе на «Избранное» и восстанавливается при возврате на «Все». Это осознанное решение по контракту.
- Если сохранённый тег исчез из `tags`, безопасный дефолт — автосброс на «Все» с коротким уведомлением, а не пустой экран с несуществующим чипом.
- Фильтр не сохраняется в URL и не шарится ссылкой; параметр `tag` используется только для запроса к API.
- UI показывает собственные русские сообщения об ошибках и не выводит поле `error` как есть; поведение для `400`/`500` зафиксировано в FR-031 и FR-035, текст уведомления об исчезнувшем теге — в FR-034.
- Сервер отдаёт не более текущего размера страницы (сейчас 12) подборок после фильтрации; ноль — валидный пустой результат, а не ошибка. Внутренние ошибки чтения остаются `500`.
- «Ещё подборки» уважает активный фильтр и загружает новую случайную выборку внутри выбранного тега; повтор ранее показанных карточек между запросами не запрещён.
- В `tags` попадают только значения, пригодные для фильтрации, поэтому UI не может отправить тег длиннее 64 символов. Ограничение `400` остаётся для прямых клиентов API.
- Избранное и корзина существуют и работают; фича не меняет их правила, включая поведение избранного для неактивных подборок.
- Схема БД, формат хранения тегов и существующий формат ответа не меняются; добавляются только `tags` и `active_tag`.
- Все интерактивные элементы фильтра рассчитаны на русскоязычный интерфейс и нажатие пальцем на мобильном устройстве.

## Out of Scope

- Изменение схемы БД, серверного формата хранения тегов, логики избранного и корзины.
- Выбор нескольких тегов одновременно, поиск по тексту, сортировка, счётчики подборок на чипах.
- Сохранение фильтра в URL, шаринг ссылки с фильтром, серверное состояние фильтра.
- Новые эндпоинты, включая отдельный `/api/tags`.
- Новые визуальные темы, переработка карточек или вкладок сверх скрытия чипов на «Избранном».
- Изменение кодов и сообщений ошибок других эндпоинтов.
