# Контракт HTTP API: фильтр подборок по тегу

**Статус**: согласован с `contract.md` и итоговой `spec.md`.

**Область**: только `GET /api/collections`. Остальные эндпоинты не
меняются.

## 1. Запрос

```http
GET /api/collections
GET /api/collections?tag=<значение>
Accept: application/json
```

| Параметр | Обязательность | Правило |
| --- | --- | --- |
| `tag` | необязательный | ровно один раз; отсутствует, пуст или только Unicode whitespace — без фильтра |

Отдельного `/api/tags` нет. `tag` не сохраняется на сервере и не
участвует в URL-состоянии UI.

## 2. Порядок обработки

1. Разобрать `r.URL.RawQuery` через `url.ParseQuery`; ошибка разбора —
   `400 {"error":"invalid query"}`.
2. Если значений `tag` больше одного — `400 {"error":"tag must be specified once"}`.
3. Если значение одно — проверить `utf8.ValidString`; невалидный UTF-8 —
   `400 {"error":"tag must be valid UTF-8"}`.
4. Обрезать значение через `strings.TrimSpace` (Unicode whitespace).
5. Пустая строка после обрезки — фильтра нет, `active_tag: ""`.
6. Если `utf8.RuneCountInString(tag) > 64` — `400 {"error":"tag is too long"}`.
7. Прочитать активный пул `WHERE active = 1`.
8. Построить `tags` из активного пула.
9. Найти канонический тег через `strings.EqualFold` (simple folding).
10. Если тег найден — отфильтровать подборки, где хотя бы один
    обрезанный тег равен каноническому без учёта регистра.
11. Если тег не найден — `collections: []`, `tags` и `favorites`
    полные, `active_tag` = обрезанный запрос.
12. Перемешать отфильтрованный набор и взять `min(PerPage, len)`.
13. Прочитать полный список избранного посетителя.

Шаги 1–6 выполняются до обращения к store. Ошибка store — `500`, а не
пустой результат.

## 3. Успешный ответ `200`

```json
{
  "collections": [
    {
      "id": "dinner-500-1792666479",
      "slug": "dinner-500",
      "title": "Ужин на двоих",
      "subtitle": "Простой ужин без лишних трат",
      "template": "dinner-500",
      "budget": 500,
      "total": 0,
      "items": [],
      "tags": ["ужин", "бюджет"],
      "created_at": "2026-10-22T12:00:00Z",
      "generation": 1792666479
    }
  ],
  "favorites": ["friends-lunch-1792666479"],
  "tags": ["бюджет", "завтрак", "перекус", "ужин"],
  "active_tag": "ужин"
}
```

Пример объекта подборки сокращён; реальный объект содержит все
существующие поля `domain.Collection` без переименований. `cart_url`
по-прежнему `omitempty`.

| Поле | Тип | Правило |
| --- | --- | --- |
| `collections` | array | не `null`; не более `PerPage`; только активные подборки; при фильтре — только с тегом |
| `favorites` | array string | не `null`; полный список избранного; не зависит от фильтра |
| `tags` | array string | не `null`; все доступные теги активного пула; без дублей; отсортированы сервером |
| `active_tag` | string | канонический тег, эхо обрезанного запроса или `""` |

### Правила `tags`

- Значения из данных обрезаются по краям через `strings.TrimSpace`
  (Unicode whitespace).
- Пустые и длиннее 64 Unicode-символов не включаются.
- Варианты, равные по `strings.EqualFold` (simple folding), дают одно
  значение.
- Каноническое значение — вариант с наименьшей последовательностью
  кодовых точек Unicode.
- Порядок — по возрастанию кодовых точек Unicode.
- `tags` не сужается до результата фильтра и не зависит от случайной
  выборки.

### Правила `active_tag`

| Ситуация | `active_tag` |
| --- | --- |
| `tag` отсутствует/пуст/только Unicode whitespace | `""` |
| тег совпал с пулом | каноническое написание из пула |
| тег не совпал с пулом | обрезанный запрос (эхо) |
| совпадение в другом регистре | каноническое написание, как в `tags` |

`active_tag` не содержит Unicode whitespace по краям.

## 4. Ошибки

### `400`

```json
{ "error": "tag is too long" }
```

```json
{ "error": "tag must be specified once" }
```

```json
{ "error": "invalid query" }
```

```json
{ "error": "tag must be valid UTF-8" }
```

- Поле `error` машинно-ориентированное; UI не показывает его как есть.
- Ответ `400` не содержит `collections`.
- Валидация выполняется до чтения данных.
- `invalid query` — некорректное percent-encoding; `tag must be valid
  UTF-8` — невалидный UTF-8.

### `500`

```json
{ "error": "cannot load collections" }
```

Внутренняя ошибка чтения данных не маскируется под пустой результат.

## 5. Инварианты

- `collections`, `tags`, `favorites` — массивы в любом успешном ответе.
- `tags` и `collections` одного ответа относятся к одному активному пулу.
- Внутри `collections` нет повторяющихся `id`.
- При `active_tag != ""` каждая подборка в `collections` содержит этот
  тег (или `collections` пуст, если тег неизвестен).
- `favorites` не зависит от `tag`.
- Схема БД и формат хранения тегов не меняются.
- Корзина и избранное не меняют поведение.

## 6. Проверочная матрица

| Запрос | Ожидание |
| --- | --- |
| без `tag` | `200`, `active_tag: ""`, до `PerPage` случайных активных подборок, полный `tags` |
| `tag=ужин` | `200`, только подборки с тегом, `active_tag: "ужин"` |
| `tag=УЖИН` | тот же набор, `active_tag` — каноническое написание |
| `tag=+ужин+` | пробелы обрезаны, фильтр применён |
| `tag=` или `tag=+++` | без фильтра, `active_tag: ""` |
| `tag=неизвестный` | `200`, `collections: []`, `tags`/`favorites` полные, `active_tag` — эхо |
| `tag` 64 символа | обычная обработка |
| `tag` 65 символов | `400`, поле `error`, store не вызывается |
| `tag=a&tag=b` | `400`, поле `error`, store не вызывается |
| битый percent-encoding | `400 {"error":"invalid query"}`, store не вызывается |
| невалидный UTF-8 | `400 {"error":"tag must be valid UTF-8"}`, store не вызывается |
| store вернул ошибку | `500`, поле `error` |
| подборок по тегу меньше `PerPage` | ровно столько, сколько есть |
| подборок по тегу больше `PerPage` | ровно `PerPage`, без дублей, все с тегом |
| активный тег есть у нескольких подборок | подборка с несколькими тегами попадает при совпадении любого |
| избранное при активном фильтре | полный список, как без фильтра |
