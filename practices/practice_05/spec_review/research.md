# Research: фильтр подборок по тегу

**Дата**: 2026-10-23

**Вход**: `spec.md`, `contract.md`, `gaps.md`, код
`practices/practice_04/collections`.

## 1. Что уже есть в сервисе

- `GET /api/collections` вызывает `Store.SampleActive(ctx, PerPage)` и
  возвращает `collections` и `favorites`.
- `SampleActive` делает `SELECT ... WHERE active = 1 ORDER BY RANDOM()
  LIMIT ?`; теги хранятся в JSON-колонке `collections.tags`.
- `domain.Collection.Tags` уже есть и попадает в JSON карточки.
- `PerPage` настраивается через `COLLECTIONS_PER_PAGE` (10–15, по
  умолчанию 12).
- UI на `web/app.js` держит `collections`, `favorites` и `mode`, умеет
  «Все»/«Избранное», но не имеет строки чипов, отдельных состояний
  загрузки/пустоты/ошибки и защиты от поздних ответов.
- Корзина и избранное уже работают и не требуют изменений.

## 2. Ключевые решения

### R-01. Фильтровать в Go, а не в SQL

**Решение**: читать активный пул целиком и фильтровать в Go.

**Почему**:

- теги лежат в JSON-колонке;
- SQLite `lower()` не умеет Unicode case folding для кириллицы;
- нужен канонический тег и сортировка по кодовым точкам — это проще и
  надёжнее в Go;
- активный пул — это единицы или десятки подборок, полное чтение
  допустимо.

**Отклонено**: `LIKE`/`lower(tags)` в SQLite. Даёт неверный результат для
кириллицы и не позволяет выбрать каноническое написание.

### R-02. Один снимок активного пула на запрос

**Решение**: добавить `Store.ActivePool(ctx) ([]domain.Collection, error)`,
который одним запросом читает все строки `WHERE active = 1`. Из этого же
среза строятся и `tags`, и отфильтрованные `collections`.

**Почему**: `tags` и подборки в одном ответе обязаны относиться к одному
активному пулу (FR-013, SC-017). Два отдельных запроса могли бы попасть
на смену поколения.

**Отклонено**: отдельный `ListTags` + `SampleActive`. Два запроса и риск
несогласованного ответа.

### R-03. Регистронезависимость и каноническое написание

**Решение**:

- обрезать Unicode whitespace по краям (`strings.TrimSpace`);
- сравнивать через `strings.EqualFold` — Unicode simple case folding без
  локали;
- группировать варианты, равные по `EqualFold`;
- каноническое написание — вариант с лексикографически наименьшей
  последовательностью кодовых точек;
- сортировать канонические значения по возрастанию кодовых точек
  (`sort.Strings` для UTF-8 даёт порядок кодовых точек);
- пустые значения и значения длиннее 64 Unicode-символов в `tags` не
  включать;
- исходные `Collection.Tags` не перезаписывать.

**Почему**: `strings.EqualFold` входит в stdlib и не зависит от локали.
Для кириллицы это покрывает требование; `golang.org/x/text/cases` не
подключаем из-за запрета на новые зависимости.

**Ограничение**: `strings.EqualFold` — это Unicode simple folding, а не
полный `CaseFolding.txt`. Для учебного сервиса и текущих данных этого
достаточно; поведение зафиксировано в тестах.

### R-04. Валидация параметра до чтения данных

**Решение**:

1. разобрать `r.URL.RawQuery` через `url.ParseQuery`; ошибка — `400`;
2. взять `tag`; если значений больше одного — `400` с `error`;
3. проверить `utf8.ValidString`; невалидный UTF-8 — `400`;
4. иначе обрезать значение через `strings.TrimSpace`;
5. пустое значение — фильтра нет, `active_tag: ""`;
6. длиннее 64 Unicode-символов — `400`;
7. только после этого читать активный пул.

**Почему**: FR-004, FR-007, FR-007a, FR-008 требуют `400` до обращения к
данным. `url.ParseQuery` сам декодирует URL и `+` как пробел, но ошибку
разбора нужно обработать явно; невалидный UTF-8 проверяется отдельно.

### R-05. Неизвестный тег — не ошибка

**Решение**: если после нормализации тег не совпал с `tags`, вернуть
`200`, `collections: []`, полные `tags` и `favorites`,
`active_tag` = обрезанный запрос.

**Почему**: FR-006, FR-018. UI по несовпадению `active_tag` с `tags`
понимает, что тег устарел, и делает автосброс.

### R-06. Случайная выборка после фильтрации

**Решение**: отфильтровать пул, скопировать срез, перемешать stdlib
`math/rand`, взять `min(PerPage, len)`. Без фильтра — тот же алгоритм для
всего пула.

**Почему**: FR-010, FR-011. Перемешивание после фильтра не даёт добора
из других тегов; копия не мутирует срез из store.

**Тесты**: проверяют размер, принадлежность тегу и отсутствие дублей, а
не конкретный порядок.

### R-07. Store остаётся тонким

**Решение**: store отдаёт только `ActivePool`. Нормализация, канонизация,
фильтрация и выборка — в `domain`/`httpapi`.

**Почему**: не меняется схема БД и слой хранения; правила тегов
тестируются как чистые функции.

### R-08. UI: одно состояние фильтра на вкладку «Все»

**Решение**: в `state` хранить `activeTag`, `tags`, `loading`, `error`,
`requestSeq`, `lastRequestTag`. Фильтр живёт в памяти, в URL не пишется.
При переходе на «Избранное» `activeTag` сохраняется, но не применяется;
при возврате на «Все» подборки загружаются заново с этим тегом.
`loadFavorites` синхронизирует `state.favorites` по id из
`data.collections` (endpoint `/api/favorites` не меняется); «Ещё
подборки» на «Избранном» сохраняет текущий `loadCollections`, но не
перезаписывает `activeTag` и `tags`, пока активна эта вкладка.

**Поздние ответы**: каждый запрос получает номер `requestSeq` и
запоминает `requestMode`; ответ применяется, только если номер совпадает
с текущим и вкладка не менялась. Для `loadCollections` поля
`tags`/`activeTag` обновляются только при `requestMode === "all"`, а
`collections`/`favorites` — всегда; `loadFavorites` требует активную
вкладку «Избранное». Это реализует FR-033 без `AbortController`
(GAP-08).

### R-09. Чипы во время загрузки

**Решение**: не использовать нативный `disabled` у чипов. В загрузке
выставлять `aria-disabled="true"`, оставлять элементы в Tab-порядке и
игнорировать активацию в обработчике. «Ещё подборки» можно блокировать
нативно.

**Почему**: нативный `disabled` убирает чип из фокуса и нарушает FR-051,
FR-048. Это соответствует GAP-04.

### R-10. Мобильная строка чипов

**Решение**: одна flex-строка с `flex-wrap: nowrap` и
`overflow-x: auto`, без отрицательных отступов; `min-width: 0` у
контейнера; область нажатия не меньше 44×44 CSS px; видимый
`:focus-visible`; активный чип отличается заливкой, рамкой/тенью и
жирным начертанием, а не только цветом.

**Почему**: FR-053–FR-055, SC-006. Браузер сам прокручивает
сфокусированный элемент в видимую область; дополнительно можно вызвать
`scrollIntoView({block: "nearest", inline: "nearest"})`.

### R-11. Избранное и корзина не меняются

**Решение**: `favorites` в ответе всегда полный; `/api/favorites`,
`PUT`/`DELETE` и `POST .../cart` не трогаем. На «Избранном» чипы
скрыты. Добавление в избранное и открытие корзины на отфильтрованной
карточке работают через существующие обработчики.

**Почему**: FR-012, FR-042–FR-047, FR-059.

### R-12. Тестирование UI без новых зависимостей

**Решение**: UI проверяется вручную по `quickstart.md`. В репозитории
нет JS-тест-раннера, а добавлять зависимости запрещено. Серверная логика
покрывается `go test`, включая границы и ошибки.

**Почему**: запрет на новые зависимости и минимальный scope.

### R-13. Размер страницы

**Решение**: сервер использует `Config.PerPage` (из
`COLLECTIONS_PER_PAGE`), UI показывает ровно пришедшее число карточек и
не применяет жёсткое `12`.

**Почему**: GAP-09, FR-010, FR-026. 12 — текущее значение по умолчанию.

## 3. Открытые вопросы

Нет. Поведение, влияющее на пользователя, закрыто в `contract.md`.
GAP-04, GAP-07 и GAP-08 применяются как предложения по умолчанию;
отклонений от них план не вводит.

## 4. Риски

- Полное чтение активного пула вырастет по памяти, если поколение станет
  очень большим. Сейчас это десятки подборок; при росте можно вынести
  только `id/tags` в отдельный запрос, но это уже другая задача.
- `strings.EqualFold` не покрывает редкие полные case folding-пары.
  Это осознанное ограничение stdlib-решения.
- UI не имеет автоматических тестов; регрессии ловятся ручным
  чек-листом и серверными тестами.
- Случайная выборка в тестах не должна проверять порядок — только
  размер, состав и отсутствие дублей.
