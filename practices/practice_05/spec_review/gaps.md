# Пробелы для реализации

Это не самостоятельный источник требований. Для каждого пункта описано, чего
не хватает в спеках, зачем это нужно, что предлагается по умолчанию и на что
решение повлияет.

## Статус

Предложения по умолчанию приняты как fallback, а не как отдельные требования.
GAP-01, GAP-02, GAP-03, GAP-05, GAP-06, GAP-09 и GAP-10 перенесены в
`contract.md` и итоговую `spec.md`; для них источник истины — требования и
допущения спеки. GAP-04, GAP-07 и GAP-08 применяются как fallback, если при
планировании или реализации не принято иное; любое отклонение фиксируется в
`contract.md` и `spec.md`.

## GAP-01. Точное правило канонического написания

- **Что не описано**: логика требует детерминированно выбрать одно написание
  среди вариантов, отличающихся только регистром, но не фиксирует правило.
  В предположениях приведён только пример «наименьшее в порядке кодовых точек».
- **Почему это нужно**: `tags` и `active_tag` должны быть стабильны между
  запросами и проверяемы в тестах; UI выделяет чип по `active_tag`.
- **Предложение по умолчанию**: среди вариантов после обрезки выбирать
  вариант с лексикографически наименьшей последовательностью кодовых точек
  Unicode. Правило не зависит от запроса.
- **Статус**: принято и перенесено в FR-017 и Assumptions итоговой спеки.
- **На что влияет**: значения `tags` и `active_tag`, тестовые фикстуры,
  выделение активного чипа. Пользовательское поведение не меняется, если
  правило стабильно.

## GAP-02. Детерминированный порядок `tags`

- **Что не описано**: обе спеки говорят «порядок задаёт сервер» и требуют
  детерминированности, но не называют алгоритм сортировки.
- **Почему это нужно**: без правила нельзя написать устойчивые проверки
  AC-05 и SC-007; порядок чипов должен быть одинаковым для одного набора
  данных.
- **Предложение по умолчанию**: сортировать канонические значения по
  возрастанию кодовых точек Unicode, независимо от случайной выборки
  подборок и от текущего фильтра.
- **Статус**: принято и перенесено в FR-016 и Assumptions итоговой спеки.
- **На что влияет**: порядок чипов в UI, ожидания API-тестов. Состав тегов
  не меняется.

## GAP-03. Язык и формат ошибок, которые видит пользователь

- **Что не описано**: сервер возвращает поле `error` с английским текстом
  (`tag is too long`), а UI требует русские сообщения без HTTP-кодов, имён
  полей и технических деталей. Правило преобразования не зафиксировано.
- **Почему это нужно**: иначе технический текст сервера может попасть на
  экран; также нужен предсказуемый текст для экранного доступа.
- **Предложение по умолчанию**: поле `error` остаётся машинно-ориентированным
  и не выводится как есть. UI показывает собственный русский текст по
  контексту: для `400` — сообщение о невозможности применить фильтр и
  действие сброса, для `500` — сообщение о загрузке и «Повторить».
- **Статус**: принято и перенесено в FR-031, FR-035 и `contract.md`.
- **На что влияет**: тексты интерфейса, сквозные тесты, объявления
  скринридера. Коды ответов API не меняются.

## GAP-04. Недоступность чипов во время загрузки

- **Что не описано**: UI требует, чтобы во время загрузки чипы не теряли
  фокус и оставались в порядке Tab, но при этом игнорировали активацию и
  объявлялись недоступными. Механизм не назван.
- **Почему это нужно**: нативный `disabled` убирает элемент из порядка
  фокуса и ломает требование о сохранении фокуса.
- **Предложение по умолчанию**: использовать `aria-disabled="true"` и
  программную блокировку активации, сохраняя чипы в порядке фокуса. Кнопку
  «Ещё подборки» можно блокировать нативно.
- **На что влияет**: клавиатурное поведение, атрибуты доступности,
  тесты фокуса.

## GAP-05. Текст, длительность и объявление автосброса устаревшего тега

- **Что не описано**: решение об автосбросе принято, но нет текста
  уведомления, способа показа, длительности и связи с живым регионом.
- **Почему это нужно**: пользователь должен понять, почему фильтр исчез;
  уведомление должно быть доступно без зрения.
- **Предложение по умолчанию**: показывать в статусе текст «Тег больше
  недоступен, фильтр сброшен» и объявлять его через живой регион; держать
  сообщение видимым около 5 секунд, без модального окна.
- **Статус**: принято и перенесено в FR-034 и Assumptions итоговой спеки.
- **На что влияет**: тексты, поведение статуса, проверки доступности.
  Логика сброса уже зафиксирована в контракте.

## GAP-06. Валидация тега сверх длины и нормализация Unicode

- **Что не описано**: кроме обрезки пробелов и ограничения 64 символа, не
  описаны управляющие символы, переводы строк, NUL, URL-декодирование,
  Unicode-нормализация (NFC/NFD) и вариант case folding.
- **Почему это нужно**: от этого зависит, какие значения дают `200`, `400`
  или пустой результат; это также вопрос устойчивости API.
- **Предложение по умолчанию**: сервер разбирает `RawQuery`, отклоняет
  некорректное percent-encoding и невалидный UTF-8 с `400` до чтения
  данных, обрезает Unicode whitespace по краям через `strings.TrimSpace`,
  не применяет дополнительных запретов на управляющие символы и NUL и не
  нормализует Unicode (NFC/NFD). Сравнение — Unicode simple case folding
  через `strings.EqualFold` без локали; внутренние пробельные символы
  значимы. Значения длиннее 64 кодовых точек после обрезки отклоняются.
- **Статус**: принято и перенесено в FR-003, FR-007a, FR-014 и Assumptions
  итоговой спеки.
- **На что влияет**: граничные тесты API, безопасность ввода, коды `400`,
  сравнение тегов и отображаемые чипы.

## GAP-07. Повторные выборки «Ещё подборки»

- **Что не описано**: может ли новая случайная выборка внутри тега повторять
  карточки, которые уже были показаны в предыдущей выборке.
- **Почему это нужно**: от этого зависит ожидаемый пользовательский опыт и
  формулировки тестов.
- **Предложение по умолчанию**: каждый запрос «Ещё подборки» делает новую
  случайную выборку внутри выбранного тега; повтор ранее показанных карточек
  допустим. Уникальность гарантируется только внутри одного ответа.
- **На что влияет**: UX обновления выборки и тестовые assertions. Фильтр и
  лимит 12 не меняются.

## GAP-08. Идентификация устаревших ответов и отмена запросов

- **Что не описано**: UI требует не применять поздний ответ неактивной
  вкладки, но не фиксирует, как это обеспечивается — отменой запроса или
  номером поколения.
- **Почему это нужно**: при быстром переключении вкладок и повторных
  нажатиях возможны гонки; без правила трудно проверить требование.
- **Предложение по умолчанию**: хранить счётчик запросов для вкладки и
  применять только ответ на последний запрос активной вкладки; отмену через
  `AbortController` считать необязательной оптимизацией.
- **На что влияет**: реализация загрузки, тесты гонок, расход запросов.
  Пользовательское правило «поздний ответ не меняет текущую вкладку»
  остаётся.

## GAP-09. Граница 12 при изменении конфигурации

- **Что не описано**: UI-спека называет 12 фиксированным числом, логика
  называет 12 текущим размером страницы. Не сказано, что делать при смене
  конфигурации.
- **Почему это нужно**: иначе UI и API разойдутся при изменении размера
  страницы.
- **Предложение по умолчанию**: сервер использует настроенный размер
  страницы (сейчас 12), UI отображает столько карточек, сколько пришло, и не
  добирает и не обрезает по жёсткому числу 12. В критериях приёмки 12
  фиксируется для текущей конфигурации.
- **Статус**: принято и перенесено в FR-010, FR-026, SC-003, SC-013 и
  Assumptions итоговой спеки.
- **На что влияет**: конфигурация, тексты критериев, тесты количества
  карточек.

## GAP-10. Нормализация тегов из данных

- **Что не описано**: логика предполагает, что теги в данных уже
  нормализованы, но не говорит, обрезает ли сервер пробелы у значений из
  `collection.tags` при построении `tags` и сравнении.
- **Почему это нужно**: иначе в `tags` может попасть значение с пробелами по
  краям, а `active_tag` и сравнение будут вести себя непредсказуемо.
- **Предложение по умолчанию**: при построении `tags` и при сравнении
  обрезать пробелы по краям у значений из данных; значения, ставшие пустыми,
  и значения длиннее 64 кодовых точек после обрезки в `tags` не включать.
  Исходные данные не перезаписывать.
- **Статус**: принято и перенесено в FR-003, FR-014 и Assumptions итоговой
  спеки.
- **На что влияет**: отображаемые чипы, `active_tag`, результаты фильтрации,
  граничные тесты. Схема хранения не меняется.
