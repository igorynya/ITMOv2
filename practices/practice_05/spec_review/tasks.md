# Tasks: фильтр подборок по тегу

**Input**: `practices/practice_05/spec_review/spec.md`,
`plan.md`, `contracts/`, `contract.md`.

**Prerequisites**: `plan.md`, `research.md`, `data-model.md`,
`contracts/http-api.md`, `contracts/ui-state.md`, `quickstart.md`.

**Tests**: обязательны: спека и план требуют проверок store/httpapi и
ручных сквозных сценариев. Тесты пишутся до реализации
соответствующего шага.

## Формат

- `[ID] [P?] [Story] Описание`
- `[P]` — можно делать параллельно: другой файл и нет зависимости.
- `[US1]`…`[US6]` — принадлежность к user story.
- Пути указаны от `practices/practice_04/collections/`.
- Одна задача — один небольшой логический шаг.

## Глобальные ограничения

- Только Go stdlib и уже подключённые зависимости.
- Схема БД и формат `collections.tags` не меняются.
- `collections`, `tags`, `favorites` всегда массивы, не `null`.
- Размер страницы — `Config.PerPage` (10–15, по умолчанию 12).
- Корзина и избранное не переделываются; API избранного не меняется.
- Тексты интерфейса фильтра — на русском, без HTTP-кодов и имён полей.
- Фильтр не сохраняется в URL и на сервере.

### MVP first

1. Phase 1–2: доменные правила, `ActivePool`, интерфейс.

### Incremental delivery

1. US1 → US2: выбор и сброс фильтра.
2. US3: загрузка, пустота, ошибка, повтор.
3. US4: границы API и curl-матрица.
4. US5: избранное и возврат.
5. US6: клавиатура и мобильная строка.
6. Phase 9: документация, полный прогон, сверка.
