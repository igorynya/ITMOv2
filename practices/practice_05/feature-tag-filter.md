# Фича: фильтр подборок по тегу

Бриф для двух команд. Каждая команда читает свою секцию и пишет только свою
спеку. Код на этом этапе не пишем.

## Цель

Дать пользователю возможность оставить на странице только подборки нужного
тега: «ужин», «завтрак», «перекус» и т.п. Сейчас теги есть в данных и
отображаются на карточках, но фильтра нет.

## Контекст

- Проект: `practices/practice_04/collections`.
- Страница: сетка подборок, вкладки «Все» и «Избранное».
- API: `GET /api/collections` отдаёт случайные 12 подборок и id избранного.
- Теги уже хранятся в каждой подборке (`collection.tags`).
- Избранное и корзина работают и не должны сломаться.

## Границы фичи

Входит:

- выбор одного тега;
- сброс фильтра;
- состояния загрузки, пустого результата и ошибки;
- валидация параметра на стороне API.

Не входит:

- несколько тегов одновременно;
- поиск по тексту;
- сортировка;
- сохранение фильтра в URL;
- изменение схемы БД;
- изменение корзины и избранного.

## Команда UI

Отвечает только за экран и состояния.

- Строка чипов над сеткой: «Все» и доступные теги.
- Активный чип визуально выделен; повторное нажатие сбрасывает фильтр.
- Во время запроса чипы блокируются, показывается состояние загрузки.
- Если подборок нет — пустое состояние и кнопка сброса.
- Если запрос упал — сообщение об ошибке и кнопка «Повторить».
- Фильтр применяется только к вкладке «Все». На вкладке «Избранное» чипы
  скрыты; поведение фильтра при возврате нужно согласовать.
- Доступность: чипы доступны с клавиатуры, активный чип имеет `aria-pressed`.

## Команда логики

Отвечает только за API, данные и правила.

- `GET /api/collections?tag=<значение>`.
- Пустой или отсутствующий `tag` — вернуть все подборки.
- Сравнение тега без учёта регистра.
- Неизвестный тег — `200` и пустой список `collections`.
- Слишком длинный тег (предлагаю больше 64 символов) — `400`.
- В ответе остаются текущие поля и добавляются:
  - `tags` — все доступные теги активного пула;
  - `active_tag` — каноническое значение выбранного тега или пустая строка.
- Случайная выборка применяется уже внутри отфильтрованного набора.
- Если подходящих подборок меньше 12 — вернуть сколько есть.
- Избранное, кэш корзины и существующий формат ответа не ломаются.

## Предлагаемый контракт

Запрос:

```http
GET /api/collections?tag=ужин
```

Ответ `200`:

```json
{
  "collections": [
    {
      "id": "dinner-500-1792666479",
      "title": "Ужин на двоих",
      "tags": ["ужин", "бюджет"],
      "items": [],
      "total": 0
    }
  ],
  "favorites": ["friends-lunch-1792666479"],
  "tags": ["ужин", "завтрак", "перекус"],
  "active_tag": "ужин"
}
```

Ошибка `400`:

```json
{ "error": "tag is too long" }
```

## Условия приёмки

1. При загрузке видны чип «Все» и все теги активного пула.
2. Нажатие на тег оставляет только подборки с этим тегом, порядок случайный.
3. Повторное нажатие на активный тег или «Все» сбрасывает фильтр.
4. Тег в другом регистре даёт тот же результат.
5. Неизвестный тег даёт пустой список и пустое состояние с кнопкой сброса.
6. Избранное, корзина и переход между вкладками работают как раньше.
7. При ошибке API показывается сообщение и кнопка «Повторить».

## Проверки

- Успех: выбрать «ужин», увидеть только подборки с этим тегом, сбросить.
- Ошибка: недоступный API, увидеть сообщение и повторить запрос.
- Граница: `tag=УЖИН`, `tag=неизвестный`, `tag=` из 65 символов.
- Регрессия: добавить подборку в избранное, открыть корзину до и после фильтра.

## Вопросы для согласования

1. Список тегов отдавать в `/api/collections` или отдельным `/api/tags`?
2. Фильтр на вкладке «Избранное»: не применять, сбрасывать или сохранять?
3. Нужен ли `?tag=` в URL, чтобы ссылкой можно было поделиться?
4. Что считать каноническим написанием тега в `active_tag`?
5. Показывать ли счётчик подборок рядом с чипом?
