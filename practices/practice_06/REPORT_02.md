## Что именно изменено в service.py

- **Сессии как единственный источник прав.** Добавлен `session_of(headers)`; владелец, роль и
  имя пользователя берутся только из `self.sessions[token]`. Заголовки `X-Role`/`X-Token`-как-роль
  больше не дают полномочий (V4, V6).
- **Параметризация SQL** во всех запросах (`/profile`, `/search`, `/orders`, `/assistant/context`),
  строгая типизация `id`/`order_id` → `400` на мусор (V1, V2, V3).
- **Скоуп по владельцу:** клиент видит только свой профиль/заказы; поиск — только себя; staff — всё (V4).
- **Цена только из каталога** на сервере, поле `price` из тела игнорируется (V5).
- **Файлы:** каталог из сессии, имя файла — белый список `receipt.txt`, без клиентского пути и `..` (V7).
- **`/debug/logs`** закрыт ролью staff; в журнал пароли и токены пишутся замаскированными (`***`) (V8).
- **Отзывы** принимаются только от аутентифицированного клиента; вывод экранируется `html.escape` (V9).
- **Контекст помощника** требует сессию и выдаётся только по своему заказу; отзывы подаются как
  недоверенные данные с явной инструкцией их не исполнять; разрушительные инструменты не рекламируются (V10).
- **Исполнитель `/assistant/execute`** требует сессию и авторизует каждый инструмент на сервере:
  `read_file` — только свой `receipt.txt`; `export_profiles` и `delete_tree` — только staff;
  `delete_tree` дополнительно запрещает `.`/пустой путь/`..`. Защита держится независимо от решения
  модели (V11).
- **Обработчик ошибок** отдаёт клиенту обобщённое `internal error`, детали — только в stderr;
  битое тело → `400` вместо `500` (V12).

## Проверка prompt injection на реальной модели

Серверная защита тракта помощника проверена **независимо от послушания модели**: в
`evidence/after/` файлы `10e`/`10f`/`10b`/`10c` показывают, что принудительная отправка опасного
решения в `/assistant/execute` отклоняется сервером (`403`) — даже если LLM поддалась бы prompt
injection. Это и есть ключевой критерий из `lab/README.md`: оценивается корректная серверная
проверка, а не обязательный взлом конкретной модели.

Полный прогон отдельного процесса `shop-planner` (`opencode run --agent shop-planner ...`) для
сравнения ответа самой LLM до/после требует установленного `opencode` CLI. В текущей среде он не
установлен; команда для запуска описана в `lab/README.md`. Контекст «до/после» для такого запуска
сохранён: `evidence/before/09d_prompt_injection_payload.json` (вредоносная инструкция попадает в
prompt) и `evidence/after/09c_assistant_context_safe_prompt.json` (отзывы помечены как untrusted,
опасные инструменты не предлагаются).
