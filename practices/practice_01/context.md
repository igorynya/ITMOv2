## Context Pack для первого рабочего сценария

### Факты и правила

- В API добавлен маршрут `POST /api/reviews` с сигнатурой `def create_review(payload: dict) -> dict[str, str]`.
- Тело запроса ожидается как словарь с ключом `diff` (строка), доступ по индексу `payload["diff"]`.
- `ReviewService.review(diff: str)` формирует промпт: `"Review this pull request and find problems:\n{diff}"` и вызывает `llm.generate(prompt)`.
- Ответ формируется как словарь с одним ключом: `{"comment": answer}`.
- Эндпоинт `/health` возвращает `{"status": "ok"}`.

### Формат входа и результата

- Вход (HTTP POST `/api/reviews`): JSON, ключ `diff` (string), содержимое — текст unified diff.
- Выход: JSON `{"comment": string}` — текстовый ответ LLM.

### Ограничения и запрещённые действия

- В коде не зафиксированы дополнительные ограничения (аутентификация, лимиты размера, схемы валидации) — не определено.

### Хороший пример

- Запрос:
```
POST /api/reviews
Content-Type: application/json

{"diff": "diff --git a/x b/x\n..."}
```

- Ответ:
```
200 OK
{"comment": "Найдены такие-то проблемы ..."}
```

### Плохой пример

- Запрос без ключа `diff` или с типом, отличным от строки.

### Что пока неизвестно

- Поставщик/клиент для `LLM.generate` и его ограничения по размерам/таймаутам.
- Требования к аутентификации и авторизации.
- Допустимый максимальный размер `diff`.
- Ожидаемая SLA/профиль нагрузки и требования к асинхронности.

## Как использовали AI

- Для чего: Быстрый baseline‑разбор PR‑изменений и фиксация контекста первого сценария.
- Тип промпта: Zero‑shot для первичного прохода, структурированный для итогового артефакта.
- Строка в [`prompts.md`](prompts.md): записи `P1-01`, `P1-02`.
- Что проверили и исправили сами: Сопоставили форматы входа/выхода, проверили ссылки на строки diff и соответствие фактам.
