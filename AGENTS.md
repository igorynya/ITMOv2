# Правила работы агента

## Цель и область
- Репозиторий учебный; агент помогает с небольшими фичами, правками и документацией.
- Держи изменения минимальными по объёму и по охвату.

## Политика редактирования
- По умолчанию используй ASCII; не добавляй не-ASCII, если файл его не использует или контент этого не требует.
- Не редактируй большие бинарные и сгенерированные файлы; правь только исходники.
- Не откатывай и не правь чужие изменения без явной просьбы.
- Комментарии добавляй только там, где без них сложно понять логику.

## Рабочий процесс и проверки
- После правок запускай доступные проверки проекта (тесты/линтеры/скрипты).
- При падении проверки исправь причину или откати СВОЮ правку; опиши, что сделано.
- Используй инструменты:
  - Поиск файлов: Glob
  - Поиск по содержимому: Grep
  - Чтение: Read
  - Правки: Edit
  - Bash — только для команд оболочки, когда это действительно нужно

## Вопросы и неоднозначности
- Если требование неясно или есть рискованная развилка — задай один короткий уточняющий вопрос и предложи безопасный дефолт. Иначе действуй.

## Использование skills и MCP
- humanizer-zh: используй ТОЛЬКО для редактирования/ревью китайского текста с целью убрать шаблонные выражения, сохранив факты и авторский голос.
  - Не переводить языки, не придумывать факты, не превращать вероятности в уверенные утверждения.
  - Не применять к коду, конфигам и другим не-прозаическим файлам.
- MCP-инструменты: если есть релевантный tool (индексация TODO, запуск проверок и т.п.), используй его вместо ручной логики. Обрабатывай как успешные, так и ошибочные ответы.

## Защита файлов и форматов
- Не изменяй: бинарники, артефакты сборки, внешние зависимости.
- Соблюдай форматирование и заголовки в Markdown; не ломай якоря и ссылки.
- Кодовые блоки, инлайн-код, команды, пути и URL сохраняй без изменений, если задача не про правку кода.

## Git и коммиты
- Коммить только по явной просьбе. Стадируй ровно нужные файлы.
- Не делай amend или force-push без разрешения. Сообщения коммитов — коротко по сути.

## Безопасность и производительность
- Не запускай долгие/разрушительные команды. Никогда не используй `git reset --hard`.
- Не выходи за пределы проекта без явного разрешения. Не трогай секреты.

## Отчётность
- В конце работы кратко опиши:
  - что поменялось и зачем,
  - как проверил,
  - остаточные риски или вопросы.
